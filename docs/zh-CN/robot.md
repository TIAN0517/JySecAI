# JySecAI 機器人使用說明

[English](../en-US/robot.md)

本文件說明如何透過**個人微信、企業微信、釘釘、飛書、Telegram、Slack、Discord 和 QQ 機器人**使用 JySecAI，包括平臺接入、RBAC 身份繫結、服務賬號白名單、命令、驗證與故障排查。

---

## 一、在 JySecAI 裡從哪裡配置

1. 登入 JySecAI Web 端  
2. 左側導航進入 **系統設定**  
3. 在左側設定分類中點選 **機器人設定**（位於「基本設定」與「安全設定」之間）  
4. 按平臺配置：
   - **個人微信**：點選「微信 / iLink」→「生成二維碼並繫結」，用微信掃碼確認（見 [3.4 個人微信](#34-個人微信-wechat--ilink)）
   - **釘釘**：勾選並填寫 Client ID / Client Secret
   - **飛書**：勾選並填寫 App ID / App Secret
5. 點選 **應用配置** 儲存；程式會自動重啟對應機器人連線。微信掃碼繫結成功後會自動儲存並啟用，一般無需再點。

配置會寫入 `config.yaml` 的 `robots` 段，也可在配置檔案中直接編輯。透過 Web 點選“應用配置”會自動重啟對應連線；直接手工修改 `config.yaml` 時，需要重啟 JySecAI 程序。個人微信繫結成功後程式會自動寫入 `robots.wechat` 並重啟 iLink 長輪詢。

### 最短使用路徑

平臺連線成功後，不要直接開始普通對話，先完成業務身份配置：

- **多人使用**：機器人設定選擇“逐使用者繫結” → 每位使用者在 Web 右上角頭像生成繫結碼 → 在機器人中傳送繫結命令 → 傳送 `身份` 驗證。
- **只有自己使用**：先在機器人中傳送 `身份` 複製傳送者 ID → 機器人設定選擇“專用服務賬號” → User ID 填 `admin` 或其他 RBAC 使用者 → 貼上傳送者白名單 → 應用配置 → 再次傳送 `身份` 驗證。

看到“鑑權狀態：已授權”且“實際身份”正確後，即可直接傳送普通文字與 AI 對話。

## 二、支援的平臺（長連線 / 回撥）

| 平臺     | 說明 |
|----------|------|
| 個人微信 | 使用微信 iLink 協議，Web 端掃碼繫結後長輪詢收訊息，**無需公網回撥** |
| 釘釘     | 使用 Stream 長連線，程式主動連線釘釘接收訊息 |
| 飛書     | 使用長連線，程式主動連線飛書接收訊息 |
| 企業微信 | 使用 HTTP 回撥接收訊息，被動回包 + 主動呼叫企業微信傳送訊息 API |
| Telegram | Bot API 長輪詢（getUpdates），**無需公網回撥** |
| Slack    | Socket Mode（出站 WebSocket），**無需公網回撥** |
| Discord  | Gateway WebSocket，**無需公網回撥** |
| QQ 機器人 | QQ 開放平臺 WebSocket（C2C / 群 @），**無需公網回撥** |

下面第三節會按平臺寫清：在開放平臺要做什麼、要複製哪些欄位、填到 JySecAI 的哪一欄。

## 三、各平臺配置項與詳細步驟

### 3.1 釘釘

**先搞清楚：兩種釘釘機器人不一樣**

| 型別 | 從哪裡建立 | 能否做「使用者發訊息→機器人回覆」 | 本程式是否支援 |
|------|------------|----------------------------------|----------------|
| **自定義機器人** | 釘釘群裡：群設定 → 新增機器人 → 自定義（Webhook） | ❌ 不能，只能你往群裡發訊息 | ❌ 不支援 |
| **企業內部應用機器人** | [釘釘開放平臺](https://open.dingtalk.com) 建立應用並開通機器人 | ✅ 能 | ✅ 支援 |

如果你手裡是「自定義機器人」的 Webhook 地址（`oapi.dingtalk.com/robot/send?access_token=xxx`）和加簽金鑰（`SEC...`），**不能直接填到本程式**，必須按下面步驟在開放平臺建立「企業內部應用」並拿到 **Client ID**、**Client Secret**。

---

**釘釘配置完整步驟（按順序做）**

1. **開啟釘釘開放平臺**  
   瀏覽器訪問 [https://open.dingtalk.com](https://open.dingtalk.com)，用**企業管理員**賬號登入。

2. **進入應用開發**  
   左側選 **應用開發** → **企業內部開發** → 點選 **建立應用**（或選擇已有應用）。填寫應用名稱等基本資訊後建立。

3. **拿到 Client ID 和 Client Secret**  
   - 左側點 **憑證與基礎資訊**（在「基礎資訊」下）。  
   - 頁面上有 **Client ID（原 AppKey）** 和 **Client Secret（原 AppSecret）**。  
   - 點選複製，**不要手打**，注意：數字 **0** 和字母 **o**、數字 **1** 和字母 **l** 容易抄錯（例如 `ding9gf9tiozuc504aer` 中間是數字 **504** 不是 5o4）。

4. **開通機器人並選 Stream 模式**  
   - 左側 **應用能力** → **機器人**。  
   - 開啟「機器人配置」開關。  
   - 填寫機器人名稱、簡介等（必填項按提示填）。  
   - **關鍵**：訊息接收方式要選 **「Stream 模式」**（流式接入）。若只有「HTTP 回撥」或未選 Stream，本程式收不到訊息。  
   - 儲存。

5. **許可權與釋出**  
   - 左側 **許可權管理**：搜尋「機器人」「訊息」等，勾選**接收訊息**、**傳送訊息**等機器人相關許可權，並確認授權。  
   - 左側 **版本管理與釋出**：若有未釋出配置，點選 **釋出新版本** / **上線**，否則修改不生效。

6. **填回 JySecAI**  
   - 回到 JySecAI → 系統設定 → 機器人設定 → 釘釘。  
   - 勾選「啟用釘釘機器人」。  
   - **Client ID (AppKey)** 貼上第 3 步複製的 Client ID。  
   - **Client Secret** 貼上第 3 步複製的 Client Secret。  
   - 點選 **應用配置**，然後**重啟 JySecAI**。

---

**JySecAI 釘釘欄位對照**

| JySecAI 中填寫項 | 在釘釘開放平臺的來源 |
|------------------------|------------------------|
| 啟用釘釘機器人 | 勾選即啟用 |
| Client ID (AppKey) | 憑證與基礎資訊 → **Client ID（原 AppKey）** |
| Client Secret | 憑證與基礎資訊 → **Client Secret（原 AppSecret）** |

### 3.2 飛書 (Lark)

| 配置項 | 說明 |
|--------|------|
| 啟用飛書機器人 | 勾選後啟動飛書長連線 |
| App ID | 飛書開放平臺應用憑證中的 App ID |
| App Secret | 飛書開放平臺應用憑證中的 App Secret |
| Verify Token | 事件訂閱用（可選） |

**飛書配置簡要步驟**：登入 [飛書開放平臺](https://open.feishu.cn) → 建立企業自建應用 → 在「憑證與基礎資訊」中獲取 **App ID**、**App Secret** → 在「應用能力」中開通**機器人**並啟用相應許可權 → **在「事件訂閱」中新增事件**（見下）→ 釋出應用 → 將 App ID、App Secret 填到 JySecAI 機器人設定 → 儲存。

**重要：事件訂閱**  
飛書長連線只有在開放平臺訂閱了「接收訊息」事件後才會收到使用者訊息。請在該應用的 **事件訂閱** 頁面點選「新增事件」，在「訊息與群組」下勾選 **接收訊息（im.message.receive_v1）** 或同類事件；若未新增，連線會建立成功但收不到任何訊息，表現為發訊息後本地無日誌、機器人無回覆。

**飛書許可權配置（必讀）**  
在 **許可權管理** 中需開通以下許可權（與開放平臺列表中的名稱、標識一致）；修改後需在 **版本管理與釋出** 中釋出新版本才生效。

| 許可權名稱（開放平臺中顯示） | 許可權標識 | 說明 |
|----------------------------|----------|------|
| 獲取與傳送單聊、群組訊息 | `im:message` | 收發訊息的基礎許可權，**必須開通**。 |
| 接收群聊中@機器人訊息事件 | `im:message.group_at_msg:readonly` | 群聊中 @ 機器人時收訊息，需開通。 |
| 讀取使用者發給機器人的單聊訊息 | `im:message.p2p_msg:readonly` | 單聊收訊息，**必須開通**，否則私聊發訊息沒反應。 |
| 獲取單聊、群組訊息 | `im:message:readonly` | 讀取訊息內容，**必須開通**。 |

**事件訂閱**（與許可權分開配置）：在 **事件訂閱** 中新增 **接收訊息（im.message.receive_v1）**，否則長連線收不到訊息推送。

- **單聊**：在飛書裡開啟與機器人的私聊視窗，直接發「幫助」或任意文字即可，無需 @。  
- **群聊**：在群裡只有 **@ 機器人** 後傳送的內容才會被機器人收到並回復。

### 3.3 企業微信 (WeCom)

> 企業微信目前採用「HTTP 回撥 + 主動傳送訊息 API」的方式工作：  
> - 使用者發訊息 → 企業微信以加密 XML **回撥到你的伺服器**（本程式的 `/api/robot/wecom`）；  
> - JySecAI 解密並呼叫 AI → 使用企業微信的 `message/send` 介面**主動發訊息給使用者**。

**配置概覽：**

- 在企業微信管理後臺建立或選擇一個**自建應用**。
- 在該應用的「接收訊息」處配置回撥 URL、Token、EncodingAESKey。
- 在 JySecAI 的 `config.yaml` 中填入：
  - `robots.wecom.corp_id`：企業 ID（CorpID）
  - `robots.wecom.agent_id`：應用的 AgentId
  - `robots.wecom.token`：訊息回撥使用的 Token
  - `robots.wecom.encoding_aes_key`：訊息回撥使用的 EncodingAESKey
  - `robots.wecom.secret`：該應用的 Secret（用於呼叫企業微信主動傳送訊息介面）

> **重要：IP 白名單（errcode 60020）**  
> JySecAI 使用 `https://qyapi.weixin.qq.com/cgi-bin/message/send` 主動傳送 AI 回覆。  
> 若企業微信日誌或本程式日誌中出現 `errcode 60020 not allow to access from your ip`：
>
> - 說明你的伺服器出口 IP **沒有加入企業微信的 IP 白名單**；  
> - 請在企業微信管理後臺中找到該自建應用的**「安全設定 / IP 白名單」**（具體入口可能因版本略有不同），將執行 JySecAI 的伺服器公網 IP（如 `110.xxx.xxx.xxx`）加入白名單；  
> - 儲存後等待生效，再次傳送訊息測試。
>
> 如果 IP 未加入白名單，企業微信會拒絕主動傳送訊息，表現為：  
> - 回撥介面 `/api/robot/wecom` 能正常收到並處理訊息；  
> - 但手機端**始終收不到 AI 回覆**，日誌中有 `not allow to access from your ip` 提示。

### 3.4 個人微信 (WeChat / iLink)

> 個人微信採用「Web 掃碼繫結 + iLink 長輪詢」方式工作：  
> - 在 JySecAI Web 端生成二維碼 → 用**手機微信**掃碼並確認繫結；  
> - 繫結成功後自動寫入 `config.yaml` 的 `robots.wechat`，並啟動 iLink 長輪詢（程式主動連線 `ilinkai.weixin.qq.com` 收訊息）；  
> - **無需**在伺服器上配置公網回撥 URL，也**無需**去微信開放平臺註冊應用。

**與企業微信的區別**

| 專案 | 個人微信 (iLink) | 企業微信 (WeCom) |
|------|------------------|------------------|
| 使用場景 | 個人微信私聊 | 企業微信自建應用 |
| 配置方式 | Web 端掃碼繫結 | 管理後臺配置回撥 URL + Token |
| 是否需要公網 | 否（長輪詢出站即可） | 是（需可被企業微信訪問的 HTTPS 回撥） |
| 配置段 | `robots.wechat` | `robots.wecom` |

**繫結步驟（按順序做）**

1. **登入 JySecAI Web 端**  
   左側 **系統設定** → **機器人設定** → 點選 **微信 / iLink** 卡片。

2. **（可選）勾選「啟用微信機器人」**  
   首次繫結可跳過；繫結成功後會自動勾選並啟用。

3. **生成二維碼**  
   點選 **「生成二維碼並繫結」**。頁面會顯示二維碼（約 **5 分鐘**有效；過期請重新生成）。

4. **微信掃碼確認**  
   - 用手機微信掃描頁面二維碼；  
   - 按手機提示完成確認；  
   - 若手機微信彈出**配對數字**，在 Web 頁面對應輸入框填寫並點選 **提交**（僅部分賬號需要）。

5. **等待繫結完成**  
   頁面顯示「繫結成功，微信機器人已啟用」即完成。`bot_token`、`ilink_bot_id` 等會自動寫入 `config.yaml`，程式會自動重啟 iLink 長輪詢，**一般無需手動重啟服務**。

6. **在手機微信裡測試**  
   開啟與 JySecAI 機器人的**私聊**（繫結後微信內會出現對應會話），傳送「幫助」或任意文字測試。

**JySecAI 微信欄位說明**

| 欄位 | 說明 |
|------|------|
| 啟用微信機器人 | 勾選後啟動 iLink 長輪詢；繫結成功後會自動勾選 |
| 生成二維碼並繫結 | 發起掃碼繫結流程 |
| **高階設定**（一般保持預設即可） | |
| API Base URL | 預設 `https://ilinkai.weixin.qq.com` |
| Bot Type | 預設 `3` |
| Bot Agent | 預設 `JySecAI/1.0` |
| iLink Bot ID | 繫結成功後自動填充，只讀 |

**使用方式**

- 僅支援在與機器人的**私聊**中對話，直接傳送文字即可，**不需要 @**。  
- 不支援群聊 @ 機器人（與釘釘/飛書群聊不同）。  
- 僅處理**文字訊息**；圖片、語音等會忽略或提示暫不支援。

**重新繫結**

- 若需更換繫結的微信賬號，在機器人設定頁點選 **「重新繫結」**，再次掃碼即可。  
- 若提示「該微信已繫結過，無需重複繫結」，說明該賬號此前已完成繫結。

**常見問題**

| 現象 | 處理 |
|------|------|
| 二維碼過期 | 重新點選「生成二維碼並繫結」（有效期約 5 分鐘） |
| 掃碼後要求輸入數字 | 檢視手機微信顯示的配對數字，在 Web 頁面輸入並提交 |
| 繫結成功但發訊息無回覆 | 看程式日誌是否有 `微信 iLink 長輪詢已啟動`、`微信收到訊息`；確認已勾選「啟用微信機器人」 |
| 斷網或睡眠後無回覆 | 程式會自動重連（約 5～60 秒）；仍無回覆可重啟 JySecAI |
| 無法生成二維碼 | 確認伺服器能訪問 `https://ilinkai.weixin.qq.com`（出站 HTTPS） |

### 3.5 Telegram

> Telegram 使用 **Bot API 長輪詢**（`getUpdates`）：程式主動連線 `api.telegram.org` 收訊息，**無需公網回撥**。

**配置步驟：**

1. 在 Telegram 中找 **@BotFather**，傳送 `/newbot` 建立機器人，獲得 **Bot Token**。  
2. JySecAI → **系統設定** → **機器人設定** → **Telegram**。  
3. 勾選「啟用 Telegram 機器人」，貼上 **Bot Token**。  
4. （可選）填寫 Bot Username（不含 `@`），或留空由程式自動 `getMe`。  
5. （可選）勾選「允許群聊」— 群聊中僅響應 **@機器人** 的訊息。  
6. 點選 **應用配置**（會自動重啟長輪詢連線）。

**使用：** 與機器人私聊直接發訊息；群聊需 @ 機器人（且已勾選允許群聊）。

### 3.6 Slack

> Slack 使用 **Socket Mode**（出站 WebSocket）：需 **Bot Token** 與 **App-Level Token**，**無需公網回撥**。

**配置步驟：**

1. 在 [Slack API](https://api.slack.com/apps) 建立 App → 啟用 **Socket Mode**。  
2. **Basic Information** → **App-Level Tokens** → 建立 token（scope: `connections:write`），即 **xapp-** 開頭。  
3. **OAuth & Permissions** → 新增 Bot Token Scopes：`app_mentions:read`、`chat:write`、`im:history`、`im:read` 等 → 安裝到工作區，獲得 **xoxb-** Bot Token。  
4. **Event Subscriptions** → 訂閱 `message.im`、`app_mention` 等（Socket Mode 下在應用內配置）。  
5. 在 JySecAI 填入 Bot Token 與 App-Level Token → **應用配置**。

**使用：** 與 Bot 私聊直接發；頻道中需 @ 機器人。

---

### 3.7 Discord

> Discord 使用 **Gateway WebSocket**：程式主動連線 Discord Gateway，**無需公網回撥**。

**配置步驟：**

1. 在 [Discord Developer Portal](https://discord.com/developers/applications) 建立應用 → **Bot** → 複製 **Token**。  
2. 開啟 **Privileged Gateway Intents** 中的 **Message Content Intent**（否則讀不到訊息正文）。  
3. OAuth2 → URL Generator → scopes: `bot` → 許可權勾選 **Send Messages**、**Read Message History** 等 → 邀請 Bot 到伺服器。  
4. JySecAI → **機器人設定** → **Discord** → 填入 Token → **應用配置**。  
5. （可選）勾選「允許伺服器頻道」— 頻道中僅響應 **@機器人**。

**使用：** 與 Bot 私聊直接發；伺服器頻道需 @ 機器人（且已勾選允許伺服器頻道）。

---

### 3.8 QQ 機器人

> QQ 機器人使用 **QQ 開放平臺 WebSocket**（官方 `botgo` SDK）：支援 C2C 私聊與群 @，**無需公網回撥**（WebSocket 出站連線）。

**配置步驟：**

1. 在 [QQ 機器人開放平臺](https://q.qq.com) 建立機器人，獲取 **App ID** 與 **Client Secret**。  
2. 在沙箱中新增測試成員（上線前僅沙箱可對話）。  
3. 訂閱 **C2C 訊息**、**群 @ 訊息** 等事件（WebSocket 模式）。  
4. JySecAI → **機器人設定** → **QQ 機器人** → 填入 App ID、Client Secret。  
5. 測試階段勾選 **沙箱環境**；正式上線後取消沙箱併發布。  
6. 點選 **應用配置**。

**使用：** 與機器人 C2C 私聊直接發；QQ 群中需 @ 機器人。

> 注意：QQ 官方正逐步推廣 Webhook 回撥；當前實現使用 WebSocket（與釘釘/飛書類似的長連線模式）。若配置變更後連線未重新整理，可重啟 JySecAI 程序。

## 四、RBAC 鑑權與機器人命令

平臺 Token、簽名或長連線憑證只負責證明“訊息來自該平臺”；真正能執行哪些操作，由 JySecAI 的 RBAC 決定。每個機器人例項都必須選擇一種業務鑑權模式。

### 4.1 應該選擇哪種模式

| 使用場景 | 推薦模式 | 身份與資料範圍 |
|----------|----------|----------------|
| 企業微信、飛書、釘釘、Slack 等多人共享機器人 | `user_binding` | 每個傳送者繫結自己的 Web 使用者，許可權和資料互相隔離 |
| 個人微信、單人專屬機器人、固定自動化入口 | `service_account` | 白名單傳送者統一使用配置的 RBAC 使用者，並共享該賬號的資料 |

兩種模式都會在**每條訊息**執行前重新讀取使用者狀態、角色、逐許可權 Scope 和資源授權。使用者被禁用或許可權被收回後，下一條訊息立即失效。

機器人執行普通 AI 對話至少需要以下許可權：

```text
agent:execute
chat:read
chat:write
```

使用專案、角色、本地命令、WebShell、C2 或外部 MCP 時，還需按功能增加對應許可權。刪除對話需要 `chat:delete`。

### 4.2 逐使用者繫結模式（預設）

管理員操作：

1. 系統設定 → 機器人設定 → 選擇平臺。
2. 在“業務鑑權策略”中選擇“逐使用者繫結（`user_binding`）”。
3. 點選“應用配置”。

每位使用者操作：

1. 登入 JySecAI Web，點選右上角頭像 → **繫結機器人賬號**。
2. 點選 **生成繫結碼**，頁面開始 5 分鐘倒計時。
3. 在目標機器人中傳送頁面給出的完整命令，例如 `繫結 7C6E-BD4C`。
4. 傳送 `身份` 或 `whoami`，確認“鑑權狀態：已授權”且“實際身份”是自己的 Web 使用者。

繫結碼僅儲存雜湊、只能使用一次。倒計時結束後前端會標記失效、禁用複製並重新整理繫結列表；服務端也會拒絕過期碼。重新生成會讓此前尚未使用的舊碼立即失效。使用者可傳送 `解綁`，或在 Web 繫結視窗中撤銷繫結。

### 4.3 專用服務賬號模式

1. 先讓機器人正常連線平臺。
2. 目標使用者向機器人傳送 `身份` / `whoami`，複製返回的完整“傳送者 ID”。個人微信的 ID 通常形如 `xxxx@im.wechat`；必須以命令返回值為準，不能用 `ilink_bot_id` 或配置中的 `ilink_user_id` 代替。
3. 系統設定 → 機器人設定 → 選擇平臺 → 業務鑑權策略選擇“專用服務賬號（`service_account`）”。
4. 填寫服務賬號的 **RBAC User ID**，不是顯示名稱。可以填寫 `admin`；此時白名單傳送者擁有完整平臺許可權，介面會顯示紅色風險提示。
5. 在“允許的平臺傳送者 ID”中每行填寫一個完整 ID。必須精確匹配、區分大小寫，不允許 `*` 萬用字元。
6. 點選“應用配置”，再傳送 `身份` 確認“實際身份”和角色正確。

示例：

```yaml
robots:
  wechat:
    auth:
      mode: service_account
      service_user_id: admin
      allowed_external_users:
        - "o9cq806s32Sm2_kyOmkyaV7Rn1lU@im.wechat"
```

服務賬號模式不接受 `繫結` / `解綁` 命令。多個白名單傳送者會共享服務賬號建立的對話、專案和其他 `own` 範圍資源；若不希望共享，請使用逐使用者繫結。

### 4.4 如何檢查當前身份

傳送：

```text
身份
```

返回內容包含：平臺、真實傳送者 ID、鑑權模式、鑑權狀態、實際 RBAC 使用者、RBAC User ID、平臺角色、資源範圍和有效許可權數量。不在服務賬號白名單中的傳送者只會看到拒絕狀態，不會看到服務賬號詳情。

### 4.5 命令列表

在任一已接入平臺（釘釘/飛書/微信/Telegram/Slack/Discord/QQ 等）向機器人傳送以下**文字命令**（僅支援文字）：

| 命令 | 說明 |
|------|------|
| **繫結 \<繫結碼\>** | 將當前平臺傳送者繫結到生成繫結碼的 RBAC 使用者 |
| **解綁** | 解除當前平臺賬號繫結；也可在 Web 端的繫結列表中撤銷 |
| **身份** 或 **whoami** | 顯示平臺傳送者 ID、鑑權模式、繫結狀態及當前實際 RBAC 使用者、角色和資源範圍 |
| **幫助** | 顯示命令幫助與說明 |
| **列表** 或 **對話列表** | 列出所有對話的標題與對話 ID |
| **切換 \<對話ID\>** 或 **繼續 \<對話ID\>** | 指定對話 ID，後續訊息在該對話中繼續 |
| **新對話** | 開啟一個新對話，後續訊息在新對話中 |
| **清空** | 清空當前對話上下文（效果等同「新對話」） |
| **當前** | 顯示當前對話 ID 與標題 |
| **停止** | 中斷當前正在執行的任務 |
| **角色** 或 **角色列表** | 列出所有可用角色（滲透測試、CTF、Web 應用掃描等） |
| **角色 \<角色名\>** 或 **切換角色 \<角色名\>** | 切換當前使用的角色 |
| **刪除 \<對話ID\>** | 刪除指定對話 |
| **版本** | 顯示當前 JySecAI 版本號 |

除以上命令外，**直接輸入任意文字**會作為使用者訊息發給 AI，與 Web 端對話邏輯一致（滲透測試/安全分析等）。

群聊訊息按實際傳送者鑑權，不使用群 ID 作為業務身份。服務賬號模式除外：白名單傳送者會明確共享配置的服務賬號許可權和資源。

## 五、如何使用（要 @ 機器人嗎？）

- **個人微信**：在與 JySecAI 機器人的**私聊**中直接傳送即可，**不需要 @**（不支援群聊）。  
- **釘釘 / 飛書單聊（推薦）**：**搜尋並開啟該機器人**，進入**私聊**，直接輸入「幫助」或任意文字即可，**不需要 @**。  
- **釘釘 / 飛書群聊**：若機器人被新增到群裡，在群內只有 **@機器人** 後傳送的訊息才會被機器人收到並回復；不 @ 的群訊息不會觸發機器人。

總結：**個人微信、單聊時直接發**；**釘釘/飛書在群裡用時需要 @機器人** 再發內容。

## 六、推薦使用流程（避免漏步驟）

**個人微信（最簡單，無需開放平臺）**

1. JySecAI Web 端 → 系統設定 → 機器人設定 → **微信 / iLink** → **生成二維碼並繫結**。  
2. 手機微信掃碼確認（如需配對數字則在 Web 頁填寫）。  
3. 在手機微信私聊中傳送 `身份`，複製傳送者 ID。  
4. 回到機器人設定選擇 `user_binding`，或選擇 `service_account` 並填寫服務賬號與傳送者白名單。  
5. 點選應用配置，在微信中再次傳送 `身份`，確認實際 RBAC 身份後再傳送普通訊息。

**釘釘 / 飛書**

1. **在開放平臺**：按第三節完成應用建立、憑證複製、機器人開通（釘釘務必選 **Stream 模式**）、許可權與釋出。  
2. **在 JySecAI**：系統設定 → 機器人設定 → 勾選對應平臺，貼上 Client ID/App ID、Client Secret/App Secret → 點選 **應用配置**。  
3. **選擇鑑權模式**：多人使用建議 `user_binding`；專用機器人配置服務賬號與傳送者白名單。  
4. **應用配置**：Web 會自動重啟對應連線。  
5. **在手機釘釘/飛書**：找到機器人（單聊直接發，群聊需 @），先發 `身份` 檢查鑑權，再發普通內容測試。

若發訊息沒反應，先看 **第九節排查** 和 **第十節常見彎路**。

## 八、如何驗證是否可用（無需釘釘/飛書客戶端）

在未安裝釘釘或飛書時，可用**測試介面**驗證機器人邏輯是否正常：

1. 使用具有全域性 `robot:write` 許可權的賬號登入並獲取 Bearer Token。  
2. 使用 curl 呼叫測試介面：

```bash
# 先登入；請按實際地址、使用者名稱和密碼修改
TOKEN=$(curl -s -X POST "http://localhost:6688/api/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"YOUR_PASSWORD"}' | jq -r '.token')

curl -X POST "http://localhost:6688/api/robot/test" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"platform":"dingtalk","user_id":"test_user","text":"幫助"}'
```

若返回 JSON 中含有 `"reply":"【JySecAI 機器人命令】..."`，說明命令處理正常。`幫助`、`版本` 和 `身份` 可在未繫結時執行；`列表`、`當前` 和普通 AI 訊息會走真實 RBAC，測試用 `platform + user_id` 必須已經繫結，或與服務賬號模式的傳送者白名單精確匹配。

介面說明：`POST /api/robot/test`（需全域性 `robot:write`），請求體 `{"platform":"可選","user_id":"可選","text":"必填"}`，響應 `{"reply":"回覆內容"}`。該介面僅模擬機器人業務邏輯，不驗證第三方平臺簽名或長連線。

## 九、發訊息沒反應時排查

### 9.1 個人微信

按順序檢查：

1. **是否已完成掃碼繫結**  
   機器人設定頁應顯示「已連線」或已繫結 Bot ID；`config.yaml` 中 `robots.wechat.bot_token` 不應為空。

2. **是否已啟用**  
   確認「啟用微信機器人」已勾選；若剛修改過，可重啟 JySecAI 程序。

3. **看程式日誌**  
   - 啟動後應看到：`微信 iLink 長輪詢已啟動`；  
   - 發訊息後應有：`微信收到訊息`；若沒有，多為未繫結成功或 `bot_token` 失效，可嘗試 **重新繫結**。  
   - 若出現 `微信 iLink 長輪詢異常，將自動重連`，等待自動重連或重啟程序。

4. **網路**  
   伺服器需能訪問 `https://ilinkai.weixin.qq.com`（出站 HTTPS）。繫結階段若無法生成二維碼，優先檢查此項。

5. **斷網或睡眠後**  
   與釘釘/飛書類似，程式會**自動重連**（約 5～60 秒）；仍無回覆可重啟 JySecAI。

### 9.2 釘釘

按順序檢查：

0. **筆記本合蓋睡眠 / 斷網後**  
   釘釘、飛書均使用長連線收訊息，睡眠或斷網後連線會斷開。程式會**自動重連**（約 5 秒～60 秒內重試）。喚醒或恢復網路後稍等一會兒再發訊息；若仍無反應，可重啟 JySecAI 程序。

1. **Client ID / Client Secret 是否與開放平臺完全一致**  
   從「憑證與基礎資訊」裡**複製貼上**，不要手打。注意數字 **0** 與字母 **o**、數字 **1** 與字母 **l**（例如 `ding9gf9tiozuc504aer` 中間是 **504** 不是 5o4）。

2. **配置是否已應用**  
   在 Web 端修改後必須點選“應用配置”，程式會自動重啟對應連線。若直接手工編輯 `config.yaml`，則需重啟 JySecAI 程序。

3. **看程式日誌**  
   - 啟動後應看到：`釘釘 Stream 正在連線…`、`釘釘 Stream 已啟動（無需公網），等待收訊息`。  
   - 若出現 `釘釘 Stream 長連線退出` 且帶錯誤資訊，多為 **Client ID / Client Secret 錯誤**或**開放平臺未開通流式接入**。  
   - 在釘釘裡發一條訊息後，若有收到，應有日誌：`釘釘收到訊息`；若沒有，說明釘釘未把訊息推到本程式（回頭檢查開放平臺「機器人」是否開通、是否選用 **Stream 模式**）。

4. **開放平臺側**  
   應用需已**釋出**；在「機器人」能力中需開啟**流式接入（Stream）** 用於接收訊息（僅 HTTP 回撥不夠）；許可權管理裡需有機器人接收、傳送訊息等許可權。

### 9.3 收到回覆但提示未繫結、白名單拒絕或許可權不足

1. 先傳送 `身份`，檢視“鑑權模式”和“鑑權狀態”。
2. `user_binding` 顯示未繫結：在 Web 右上角頭像中生成繫結碼，並在同一個平臺賬號中傳送完整繫結命令。繫結碼過期或已經使用時需重新生成。
3. `service_account` 顯示白名單拒絕：把 `身份` 返回的完整傳送者 ID 原樣加入當前平臺的白名單，注意大小寫、租戶字首和 `@im.wechat` 等字尾。
4. 顯示實際身份但提示缺少許可權：在“平臺許可權”檢查該 RBAC 使用者的角色。普通 AI 對話至少需要 `agent:execute`、`chat:read`、`chat:write`。
5. 服務賬號不存在或被禁用：應用配置會拒絕儲存；恢復使用者或選擇其他已啟用 RBAC 使用者。
6. 使用 `admin` 時仍被拒絕：通常是傳送者不在精確白名單中，而不是 admin 許可權不足。

## 十、常見彎路（避免踩坑）

- **個人微信與企業微信混淆**：個人微信走 `robots.wechat` + Web 掃碼繫結；企業微信走 `robots.wecom` + 管理後臺回撥 URL，二者完全不同。  
- **個人微信二維碼過期**：二維碼約 5 分鐘有效，過期需重新生成，不要一直掃舊碼。  
- **用錯了機器人型別**：在釘釘**群裡**新增的「自定義」機器人（Webhook + 加簽）**不能**用來做對話，本程式只支援**開放平臺「企業內部應用」**裡的機器人。  
- **改完沒有點應用配置**：Web 中修改機器人配置後要點選“應用配置”；程式會自動重啟對應連線。只有手工編輯 YAML 時才需要重啟程序。  
- **把 Bot ID 當成傳送者 ID**：服務賬號白名單必須填寫 `身份` 命令返回的“傳送者 ID”，不要填 `ilink_bot_id`、`ilink_user_id`、群 ID 或顯示暱稱。  
- **繫結碼過期後繼續使用**：繫結碼 5 分鐘有效且只能使用一次；新生成的碼會讓舊碼立即失效。  
- **服務賬號誤以為資料隔離**：同一服務賬號白名單中的傳送者共享該賬號的對話和 `own` 範圍資源；需要隔離時應使用 `user_binding`。  
- **admin 配置後任意人都能用**：不會。即使服務賬號是 `admin`，傳送者仍必須與白名單精確匹配；但白名單中的人將擁有完整許可權。  
- **Client ID 抄錯**：開放平臺是 `504` 就填 `504`，不要填成 `5o4`；儘量用複製貼上。  
- **釘釘只開了 HTTP 回撥沒開 Stream**：本程式透過 **Stream 長連線**收訊息，開放平臺裡機器人的訊息接收方式必須選 **Stream 模式**。  
- **應用沒釋出**：開放平臺裡修改了機器人或許可權後，要在「版本管理與釋出」裡**釋出新版本**，否則不生效。

## 十一、注意事項

- 各平臺均**僅處理文字訊息**；其他型別（如圖片、語音）會提示暫不支援或忽略。  
- 個人微信僅支援**私聊**，不支援群聊 @ 機器人。  
- 會話與 Web 端共用同一套資料：`user_binding` 下歸屬於繫結使用者；`service_account` 下歸屬於服務賬號，並由白名單傳送者共享。  
- 機器人執行與 **Eino 單/多代理** 相同邏輯（`ProcessMessageForRobot`，含進度回撥與過程詳情入庫），僅不向客戶端推送 SSE，最後一次性回覆個人微信/釘釘/飛書/企業微信。預設 `robot_default_agent_mode: eino_single`。
