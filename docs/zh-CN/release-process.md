# 釋出流程

本文用於維護者或部署者釋出、升級和回滾 JySecAI。

## 版本準備

釋出前檢查：

- `README.md` 和 `README_CN.md` 的功能說明是否更新。
- `docs/` 是否補充新功能文件。
- `config.yaml` 示例是否包含新增配置。
- OpenAPI 是否包含新增介面。
- 中英文 i18n 是否同步。
- 高風險功能是否有安全說明。

## 測試

至少執行：

```bash
go test ./internal/...
```

如果修改了入口、構建或命令：

```bash
go test ./cmd/...
go build -o jysecai ./cmd/server
```

如果修改前端，手動驗證：

- 登入。
- 對話流式輸出。
- 設定儲存和應用。
- 工具列表。
- 相關頁面無控制檯錯誤。

## 構建

```bash
go build -o jysecai ./cmd/server
```

釋出包應包含：

- `jysecai`
- `web/templates/`
- `web/static/`
- `config.yaml` 示例。
- `tools/`
- `roles/`
- `skills/`
- `agents/`
- `docs/`
- `README.md` / `README_CN.md`
- `LICENSE`

不要把本地 `data/`、真實 `config.yaml` 金鑰、上傳附件和日誌打進公開發布包。

## 升級檢查清單

升級前：

- 停服務。
- 備份 `config.yaml`。
- 備份 `data/`。
- 備份自定義 `tools/roles/skills/agents/knowledge_base`。
- 記錄當前版本和啟動方式。

升級後：

- 啟動服務。
- 登入。
- 測試模型。
- 檢查工具列表。
- 檢查知識庫狀態。
- 檢查外部 MCP。
- 檢查 C2/WebShell 是否按預期啟用或關閉。
- 檢視日誌和審計。

## 回滾

觸發回滾的常見情況：

- 服務無法啟動。
- 資料庫遷移失敗。
- 核心對話功能不可用。
- 高風險功能行為異常。

回滾步驟：

1. 停止新版本。
2. 恢復舊二進位制或舊程式碼。
3. 恢復升級前 `config.yaml`。
4. 恢復升級前 `data/`。
5. 啟動舊版本並驗證。

如果新版已修改資料庫結構，必須恢復資料庫備份，不能只替換二進位制。

## Changelog 建議

每個版本記錄：

- 新增功能。
- 行為變更。
- 配置變更。
- 資料庫變更。
- 安全修復。
- 相容性說明。
- 升級注意事項。

高風險模組的變更要單獨標出，例如 C2、WebShell、終端、外部 MCP、HITL。

## 釋出風險分級

| 改動 | 風險 | 必測 |
| --- | --- | --- |
| 文件、圖片 | 低 | 連結和渲染 |
| 前端頁面 | 中 | 登入、頁面狀態、API 錯誤 |
| Handler/API | 中 | OpenAPI、許可權、錯誤碼 |
| 配置結構 | 高 | 舊配置相容、ApplyConfig |
| 資料庫結構 | 高 | 舊庫遷移、回滾策略 |
| Agent/MCP/HITL | 高 | 工具呼叫、審批、流式中斷 |
| C2/WebShell/Terminal | 極高 | 授權環境、審計、禁用開關 |

釋出說明裡要按風險級別提示使用者，而不是隻列功能點。

## 配置相容策略

新增配置欄位要遵循：

- 省略時有安全預設值。
- 舊配置能啟動。
- 示例 `config.yaml` 有註釋。
- Web 設定頁不會把未知欄位誤刪。
- 熱應用和重啟兩種路徑都驗證。

如果新增欄位預設開啟高風險功能，應重新考慮預設值。

## 資料庫變更策略

SQLite 遷移要考慮：

- 使用者可能從很老版本直接升級。
- 遷移中斷後再次啟動是否冪等。
- 新欄位是否允許空值。
- 索引是否會鎖表太久。
- 是否需要資料回填。

釋出說明必須寫清楚“升級前備份 data/”。

## Release 驗收指令碼思路

最小自動化：

```bash
go test ./internal/...
go test ./cmd/...
go build -o jysecai ./cmd/server
```

手動冒煙：

```text
登入 -> 模型測試 -> 新建對話 -> 工具列表 -> HITL -> 知識庫 -> 外部 MCP -> 關閉/開啟 C2
```

對高風險模組，寧可多做一個授權靶場測試，也不要只靠單測放行。
