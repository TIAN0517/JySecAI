# 安全模型

JySecAI 面向授權安全測試場景，內建命令執行、MCP 工具、WebShell、C2、批次任務和多代理編排等能力。部署者必須把它當作高許可權安全工具管理，而不是普通聊天應用。

## 信任邊界

主要邊界：

- Web 登入使用者：可以發起對話、呼叫工具、修改配置、管理 WebShell/C2/知識庫。
- Agent：根據角色、工具列表、HITL 策略呼叫內建或外部工具。
- MCP 工具：可能訪問本機檔案、執行命令、呼叫外部服務或操作目標系統。
- 外部 MCP：由第三方程序或遠端服務提供，需單獨信任。
- 機器人入口：企業微信、釘釘、飛書等回撥入口不走 Web 登入，但有平臺驗籤和速率限制。

如果一個賬號可以登入 Web，就應視為擁有該 JySecAI 例項的操作許可權。

## 認證與會話

Web 登入憑據由 RBAC 使用者管理（預設內建 `admin` 賬號）。建議：

- 首次部署後立即修改 `admin` 初始密碼（控制檯首次啟動會輸出）。
- 使用長隨機密碼，並限制分享範圍。
- 將服務放在內網、VPN、堡壘機或反向代理認證後面。
- 生產環境開啟 HTTPS，避免明文傳輸 Cookie。
- 結合反向代理限制來源 IP。

登入態有效期由 `auth.session_duration_hours` 控制。

## 工具執行風險

工具來源包括：

- 內建安全執行工具。
- `tools/` 下的 YAML 命令工具。
- Eino Skills 檔案系統工具，如 `read_file`、`write_file`、`edit_file`、`execute`。
- 外部 MCP 暴露的工具。
- C2 和 WebShell 相關 MCP 工具。

風險控制建議：

- 只啟用當前任務需要的工具。
- 高風險命令工具不要加入全域性白名單。
- 給角色繫結最小工具集合。
- 對 destructive、持久化、橫向移動、憑證操作保持人工審批。
- 外部 MCP 儘量使用本地可信程序，遠端 MCP 必須有認證和網路隔離。

## HITL

HITL 是工具呼叫前的審批層。常見模式：

- `human`：人工審批。
- `audit_agent`：審計 Agent 自動審批。
- `review_edit`：審計 Agent 可改參後放行。

建議策略：

- 新環境預設人工審批。
- 只把只讀、低風險、穩定工具加入白名單。
- 掃描類工具按目標範圍配置角色和提示詞約束。
- 寫入、刪除、執行 payload、C2、WebShell、賬號改動等操作必須謹慎審批。

詳見 [HITL 最佳實踐](hitl-best-practices.md)。

## 審計

平臺審計由 `audit` 配置控制，記錄登入、配置、資源管理等平臺操作。它不記錄完整對話正文，也不等同於取證日誌。

工具執行記錄由監控模組維護，保留時間由 `monitor.retention_days` 控制。

建議：

- 開啟 `audit.enabled`。
- 定期匯出審計日誌。
- 配置合理保留期。
- 對失敗登入、配置變更、C2/WebShell 操作重點複核。

## C2 風險

內建 C2 會啟動監聽器、生成 payload、接收會話並執行任務。僅在明確授權的靶場、內網演練或紅隊環境中啟用。

建議：

- 不使用時設定 `c2.enabled: false`。
- 不在公網暴露 C2 監聽埠，除非有明確授權和隔離。
- 對 payload 檔案、回連地址、任務輸出進行訪問控制。
- C2 任務建議走 HITL。

## WebShell 風險

WebShell 管理允許對已登記連線執行命令和檔案操作。建議：

- 只新增授權目標。
- 給連線使用清晰名稱、標籤和備註。
- 不在共享環境儲存真實生產 WebShell。
- AI 使用 WebShell 前確認目標和命令。
- 清理失效或不再授權的連線。

## 資料與隱私

本地會儲存：

- 對話和訊息：`data/conversations.db`
- 知識庫索引：`data/knowledge.db`
- WebShell、C2、漏洞、專案、任務等業務資料。
- 上傳附件：`chat_uploads/`

建議：

- 限制檔案許可權。
- 備份加密。
- 不上傳無授權的敏感資料。
- 清理不再需要的會話、附件、C2 輸出和審計日誌。

## 生產基線

最低建議：

- 強密碼 + HTTPS + 內網訪問。
- `audit.enabled: true`。
- `mcp.auth_header_value` 設定隨機值。
- 不需要時關閉 `c2.enabled`。
- 外部 MCP 最小化啟用。
- 高風險工具不進白名單。
- 定期備份和更新。

## 真實威脅模型

| 威脅 | 攻擊路徑 | 影響 | 防護點 |
| --- | --- | --- | --- |
| Web 密碼洩露 | 登入管理面，呼叫終端/WebShell/C2 | 完整接管平臺能力 | 強密碼、HTTPS、內網、反向代理認證、審計 |
| Prompt Injection | 目標頁面或文件誘導 Agent 調高許可權工具 | 越權執行工具或洩露資料 | 角色邊界、HITL、工具最小化、知識庫來源標註 |
| 外部 MCP 惡意 | MCP 服務返回誤導描述或執行副作用 | 本機或目標系統受影響 | 只接入可信 MCP、獨立執行使用者、網路隔離 |
| 工具 YAML 被篡改 | 改寫命令模板或引數 | Agent 呼叫時執行惡意命令 | 檔案許可權、程式碼審查、工具白名單 |
| C2 濫用 | 生成 payload 或下發任務到非授權目標 | 法律和業務風險 | 預設關閉、審批、事件保留、網路隔離 |
| WebShell 誤操作 | AI 或使用者在生產目標執行破壞命令 | 業務中斷或資料損壞 | 連線命名、人工確認、只讀優先、刪除過期連線 |
| 資料庫洩露 | 複製 `data/*.db` 或上傳目錄 | 對話、目標、漏洞、連線資訊洩露 | 檔案許可權、加密備份、最小保留 |

## 授權邊界寫法

每個高風險角色都應把授權邊界寫進提示詞，而不是隻依賴使用者口頭說明。示例：

```text
你只能在使用者明確給出的目標範圍內行動。若需要執行寫入、刪除、爆破、持久化、憑證訪問、C2、WebShell 或橫向移動相關操作，必須先說明目的、影響、目標和回滾方式，並等待 HITL 審批。
```

這段話不能代替技術控制，但能降低 Agent 在模糊任務中擴張行為邊界的機率。

## HITL 不是萬能保險

HITL 的風險在於審批者看到的是“工具名 + 引數 + 上下文摘要”，不是完整現實世界影響。下面幾類情況要特別保守：

- 引數看似只讀，但工具本身會觸發大量請求或寫快取。
- 命令透過 `bash -c`、指令碼、base64 包裝隱藏真實動作。
- 外部 MCP 工具描述不可信。
- WebShell 目標名稱模糊，無法確認是否生產環境。
- C2 payload 生成和分發鏈路不在平臺內。

審計 Agent 適合篩掉普通低風險請求，不適合替代人類批准破壞性動作。

## 資料最小化原則

不要把這些內容長期留在平臺裡：

- 真實客戶憑證。
- 未脫敏報告。
- 生產資料庫匯出。
- 長期有效 Cookie。
- 無關目標的掃描輸出。
- 已結束專案的 WebShell/C2 會話。

建議按專案結束流程清理：附件、WebShell 連線、C2 payload、臨時 workspace、長輸出工具記錄。
