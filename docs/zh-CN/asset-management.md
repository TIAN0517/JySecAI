# 資產管理

[English](../en-US/asset-management.md)

資產管理用於將手工錄入、網路空間測繪搜尋、HTTP API 和 Agent 任務中發現的域名、IP、埠與服務統一歸檔，形成可持續維護的資產基線。它關注三個問題：當前擁有哪些資產、哪些資產已經檢查、風險集中在哪裡。

> 資產管理面向安全測試和攻擊面治理，不替代完整的企業 CMDB。僅可錄入和掃描自有系統或已獲得明確授權的目標。

## 功能概覽

資產管理包含三個主要入口：

- **資產概覽**：統計資產總量、IP、域名、埠、近期變化、掃描覆蓋率和協議分佈。
- **資產庫**：維護資產身份、服務資訊、來源、標籤、專案歸屬、責任與業務屬性、掃描記錄和風險狀態。
- **資訊收集**：查詢 FOFA、ZoomEye、Quake 或 Shodan，並將確認歸屬的結果單條或批次寫入資產庫。

資產可以進一步發起單目標分析或批次掃描。Agent 儲存漏洞並完成掃描回寫後，資產列表會同步展示相關漏洞數量、風險等級和最近掃描時間。

概覽支援切換最近 7、30 或 90 天，展示新增/停用資產趨勢、漏洞發現趨勢（含嚴重和高危）、掃描覆蓋率、30 天內覆蓋率、從未掃描與過期資產數量，以及協議 Top 8 分佈。所有統計均受當前使用者的資產訪問範圍約束。

## 資產欄位

每條資產可記錄：

- Host、IP、域名、埠和協議；
- 頁面標題、服務或產品指紋；
- 國家/地區、省份/州和城市；
- 負責人、部門、業務系統、環境和重要性；
- 來源、來源查詢條件和標籤；
- 活躍或停用狀態；
- 所屬專案和所有者；
- 首次發現、最近發現、建立和更新時間；
- 最近掃描時間及關聯的對話、任務佇列和子任務；
- 相關漏洞數量和當前風險等級。

至少需要提供 `host`、`ip` 或 `domain` 中的一項。

## 建立資產基線

### 手工新增

進入 **資產管理 → 資產庫**，點選 **新增資產**。常見目標格式包括：

```text
https://example.com:8443
example.com
192.0.2.10:443
[2001:db8::1]:443
```

系統會盡量識別 URL、域名、IP、埠和協議。儲存前可繼續補充專案、標籤、標題、服務指紋、地理位置、負責人、部門、業務系統、環境、重要性和狀態。

### 從表格批次匯入

進入 **資產管理 → 資產庫**，點選 **批次匯入**：

1. 下載 XLSX（推薦）或 CSV 模板。
2. 在 `Assets` 工作表中填寫資產；不要修改表頭。
3. 上傳檔案，或將檔案拖入上傳區域。
4. 檢視逐行校驗結果。檔案內重複、格式錯誤和無權訪問的專案會標為錯誤。
5. 點選 **匯入有效資料**。錯誤行不會提交，預覽超過 100 行時只展示前 100 行，但提交會處理全部有效行。
6. 根據提示核對新增、更新和跳過數量。

模板欄位：

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| `target` | 條件必填 | URL、域名、IPv4、IPv6 或帶埠目標；當 `host`、`ip`、`domain` 均為空時必填 |
| `project` | 否 | 已有專案的精確名稱或專案 ID；留空表示不繫結 |
| `tags` | 否 | 逗號、中文逗號、分號或豎線分隔；最多 30 個，單個最多 64 個字元 |
| `host` | 條件必填 | 完整 URL 或 Host；可與 `target` 配合補充 |
| `ip` | 條件必填 | 合法 IPv4 或 IPv6 |
| `domain` | 條件必填 | 合法域名，國際化域名會規範化 |
| `port` | 否 | `0-65535`；留空時可從 `target` 推斷 |
| `protocol` | 否 | 如 `http`、`https`、`ssh`；留空時可從 URL 或常用埠推斷 |
| `title` | 否 | 頁面標題，最多 500 個字元 |
| `server` | 否 | 服務或產品指紋 |
| `country` / `province` / `city` | 否 | 地理歸屬資訊 |
| `responsible_person` | 否 | 負責人，最多 255 個字元 |
| `department` | 否 | 責任部門，最多 255 個字元 |
| `business_system` | 否 | 所屬業務系統，最多 255 個字元 |
| `environment` | 否 | `production`、`staging`、`testing`、`development` 或 `other` |
| `criticality` | 否 | `critical`、`high`、`medium` 或 `low` |
| `status` | 否 | `active` 或 `inactive`，也接受“活躍”“停用”；預設 `active` |

表頭同時識別模板中的英文欄位和常用中文別名；環境和重要性也接受模板列中對應的中文值。為避免不同系統匯出的列名產生歧義，自動化流程仍建議使用模板中的英文表頭和列舉值。

限制與處理規則：

- 單個 XLSX/CSV 檔案最多 100000 行、100 MB。
- `/api/assets/import` 單次請求最多 100000 條資產。
- 檔案內相同“目標 + 埠 + 協議”的後續行會標記為重複，不會提交。
- Web 端負責檔案解析、預覽和即時格式提示；服務端仍會執行許可權檢查、欄位校驗、規範化、去重和事務寫入。
- 已存在的資產會合並本次提供的非空欄位並更新最近發現時間；不會建立重複記錄。
- 批次匯入需要 `asset:write` 許可權。填寫專案時，當前使用者還必須有權訪問該專案。
- 不建議取消服務端條數上限。更大規模的資料應拆分檔案並在低峰期匯入。

### 從網路空間測繪搜尋匯入

1. 在配置檔案或 **系統設定 → 資產管理** 中填寫對應 API Key，也可使用環境變數：`FOFA_API_KEY`、`ZOOMEYE_API_KEY`、`QUAKE_API_KEY`、`SHODAN_API_KEY`。
2. 進入 **資產管理 → 資訊收集**。
3. 選擇資料來源：FOFA、ZoomEye、Quake 或 Shodan。
4. 輸入或生成該資料來源的查詢語句，並確認查詢範圍。
5. 執行查詢，選擇確認歸屬的結果後點選 **入庫所選**。
6. 根據返回的新增、更新和跳過數量檢查匯入結果。

外部搜尋結果不等同於自有資產。建議先透過組織域名、證書、網段或產品指紋縮小範圍，確認授權後再入庫。

## 規範化與去重

不同入口可能使用不同形式描述同一目標。系統會執行以下處理：

- 去除欄位首尾空白；
- IP、域名和協議轉為小寫；
- 從 URL 型 Host 提取 hostname、協議和埠；
- 為未顯式指定埠的 HTTP/HTTPS 補充預設埠；
- 將國際化域名轉換為 ASCII/Punycode；
- 清理並去重標籤；
- 為缺失的狀態和來源補充預設值。

資產以“目標 + 埠 + 協議”作為服務級去重依據。目標優先採用域名，其次為 IP，最後為 Host。因此，同一主機的 `80/http` 和 `443/https` 會被視為不同資產。

重複資產再次入庫時，系統會更新本次提供的非空欄位和最近發現時間，保留未提供的原有資訊，不會重置首次發現時間。

## 查詢、篩選與檢視

Web 端的關鍵字搜尋覆蓋 Host、IP、域名、標題、服務、標籤、負責人、部門和業務系統。常用篩選包括狀態和專案；展開高階篩選後還可以組合：

- 風險等級和最少漏洞數；
- 協議、埠、來源和精確標籤；
- 已掃描、從未掃描，以及 30/60/90 天未掃描；
- 國家/地區、省份/州、城市、負責人、部門和業務系統；
- 環境、重要性、首次發現和最近發現日期範圍；
- 最近發現、最近掃描、風險、漏洞數、首次發現、目標名稱或埠排序。

按最近掃描時間升序排列時，從未掃描的資產優先顯示，便於識別覆蓋盲區。

常用篩選組合可以儲存為篩選檢視。篩選檢視儲存在當前瀏覽器的 `localStorage` 中，不會同步到服務端、其他瀏覽器或其他使用者。

HTTP API 和 `query_assets` 還支援 `max_vulnerabilities`、最近掃描時間範圍，以及建立/更新時間等白名單排序欄位。HTTP 列表每頁最多 100 條，Agent 查詢每頁最多 50 條。

## 批次維護與匯出

選擇資產後，可以對當前頁執行操作，也可以選擇當前篩選條件命中的全部結果。跨頁選擇由服務端重新解析當前篩選條件，最多返回 10000 條；超過上限時需要進一步縮小範圍。

可用操作：

- **繫結專案**：為所選資產統一替換專案歸屬；
- **批次編輯**：修改狀態、負責人、部門、業務系統、環境和重要性，並增刪標籤；
- **建立掃描任務 / 傳送到對話**：複用同一提示詞模板處理所選資產；
- **匯出 CSV / XLSX**：在瀏覽器中匯出當前已選擇的資產，包含責任屬性、風險、漏洞數量和時間欄位；
- **合併重複資產**：保留第一個所選資產為主資產，以其他記錄的非空欄位補齊主資產併合並標籤；
- **批次刪除**：永久刪除所選資產。

批次編輯、專案繫結和批次刪除採用全有或全無的事務：只要其中一個資產不存在或超出呼叫者許可權，整批操作就會失敗，不會留下部分更新。

合併僅適用於具有共同域名、IP 或 Host 的記錄，每次可選擇 2-100 條。主資產已有值優先，標籤取並集且仍受 30 個標籤限制，其餘記錄會被刪除。該操作同時需要 `asset:write` 和 `asset:delete`；合併前應確認主資產選擇以及需要保留的掃描歷史。

## 掃描與風險回寫

### 單資產掃描

在資產列表中點選 **掃描**。系統會：

1. 建立新對話並注入資產目標和資產 ID；
2. 將對話與資產關聯；
3. 引導 Agent 檢查暴露服務和授權範圍內的安全風險；
4. 使用 `record_vulnerability` 儲存確認的問題；
5. 使用 `complete_asset_scan` 回寫掃描狀態。

掃描提示詞支援 `{{asset_id}}`、`{{target}}`、`{{host}}`、`{{ip}}`、`{{domain}}` 和 `{{port}}` 變數。發起前應按授權範圍調整測試強度、埠和驗證方式。

### 批次掃描

在資產庫中選擇多個目標後，點選 **建立掃描任務**。系統會為每個資產建立獨立子任務，並建立資產、佇列和子任務之間的關聯。

當前預設使用手動排程、單併發和 Eino 單 Agent 模式，以減少對目標和本機資源的瞬時壓力。執行前仍需確認測試視窗、請求頻率、允許的驗證方式和審批要求。

### 風險計算

資產風險根據最近一次關聯掃描中的未關閉漏洞動態計算：

- `critical`、`high`、`medium`、`low`、`info`：存在對應等級的未關閉漏洞；
- `normal`：已掃描且沒有開放風險；
- `unassessed`：尚未完成掃描。

已修復、誤報或忽略的漏洞仍保留在歷史數量中，但不會繼續提高當前風險等級。

## Agent 工具

系統向 Agent 提供六個內建資產工具：

- `create_asset`：新增資產或去重更新；
- `get_asset`：按 ID 獲取完整詳情；
- `query_assets`：分頁、篩選和排序；
- `update_asset`：區域性更新；
- `delete_asset`：刪除資產；
- `complete_asset_scan`：掃描完成後回寫狀態。

`query_assets` 預設每頁返回 20 條、最多 50 條摘要。需要完整資訊時使用 `get_asset`，避免大量資產資料佔用模型上下文。

`create_asset` 和 `update_asset` 均支援責任與業務屬性；`query_assets` 也可以按這些欄位篩選。Agent 寫入仍經過與 HTTP API 相同的規範化、欄位校驗、去重和許可權檢查。

## 許可權控制

資產許可權分為：

- `asset:read`：檢視資產和統計資料；
- `asset:write`：建立、匯入、修改和回寫掃描；
- `asset:delete`：刪除資產。

服務端會同時檢查資產所有者、顯式資源授權、所屬專案及許可權 Scope（`all`、`assigned`、`own`）。當對話繫結專案後，Agent 的資產查詢會被限制在該專案內，工具引數不能擴大訪問範圍。

資產批次介面限制：

- `POST /api/assets/import`：單次最多 100000 條；
- `GET /api/assets/selection`：最多解析 10000 條匹配資產；
- `POST /api/assets/scan-links`：單次最多 10000 條；
- `PUT /api/assets/bulk`：單次最多 10000 個資產 ID；
- `PUT /api/assets/project-binding`：單次最多 10000 個資產 ID；
- `POST /api/assets/batch-delete`：單次最多 10000 個資產 ID；
- `POST /api/assets/merge`：單次合併 2-100 個資產 ID。

## 推薦使用流程

1. 劃定一組明確授權的域名、IP 或網段。
2. 手工加入少量核心目標，驗證識別和去重結果。
3. 使用標籤區分生產、測試、核心業務和外網範圍。
4. 配置一個或多個網路空間測繪搜尋引擎，從窄查詢開始並確認資產歸屬。
5. 對單個低風險目標測試掃描和漏洞回寫流程。
6. 使用“從未掃描”和“超過 30 天未掃描”篩選覆蓋盲區。
7. 確認流程穩定後，再逐步建立小規模批次任務。

經過確認的小規模資產基線通常比來源混亂的全量清單更有價值。
