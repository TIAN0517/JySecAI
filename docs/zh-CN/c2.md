# 內建 C2 使用說明

內建 C2 用於授權環境中的會話管理、任務下發、payload 生成和結果回收。不使用時建議關閉。

```yaml
c2:
  enabled: false
```

## 功能組成

主要物件：

- Listener：監聽器，負責接收會話。
- Session：上線會話。
- Task：下發給會話的任務。
- Payload：生成的載荷或 one-liner。
- Profile：通訊配置模板。
- Event：監聽器、會話、任務產生的事件。
- File：給 implant 下載或任務結果回收的檔案。

Web API 字首是 `/api/c2`。關閉 C2 時介面返回 `503 c2_disabled`。

## 監聽器

常用介面：

- `GET /api/c2/listeners`
- `POST /api/c2/listeners`
- `POST /api/c2/listeners/:id/start`
- `POST /api/c2/listeners/:id/stop`
- `DELETE /api/c2/listeners/:id`

建議給監聽器使用清晰命名，標明演練專案、網路區域和授權範圍。

## 會話

常用介面：

- `GET /api/c2/sessions`
- `GET /api/c2/sessions/:id`
- `PUT /api/c2/sessions/:id/sleep`
- `DELETE /api/c2/sessions/:id`

`sleep` 用於調整會話輪詢間隔。間隔越短，互動越實時，但流量和暴露面更高。

## 任務

常用介面：

- `GET /api/c2/tasks`
- `POST /api/c2/tasks`
- `POST /api/c2/sessions/:id/tasks`
- `POST /api/c2/tasks/:id/cancel`
- `GET /api/c2/tasks/:id/wait`
- `GET /api/c2/tasks/:id/result-file`

任務應和授權目標一致。高風險任務建議走 HITL，並在審計日誌中保留操作痕跡。

## Payload

常用介面：

- `POST /api/c2/payloads/oneliner`
- `POST /api/c2/payloads/build`
- `GET /api/c2/payloads/:id/download`

生成前確認：

- 回連地址是否正確。
- 平臺和架構是否匹配。
- 是否需要代理、sleep、profile。
- 檔案是否只在授權環境分發。

## 檔案

常用介面：

- `POST /api/c2/files/upload`
- `GET /api/c2/files`
- `GET /api/c2/tasks/:id/result-file`

上傳檔案可供 implant 下載。結果檔案可能包含敏感資訊，應按專案保密級別儲存和清理。

## MCP 工具

C2 啟用後會註冊相關 MCP 工具，供 Agent 管理監聽器、會話、任務、payload 等。建議：

- 不把 C2 工具加入全域性免審批白名單。
- 在角色提示詞中限制專案、目標、任務型別。
- 對執行命令、上傳檔案、生成 payload 的步驟開啟人工審批。

## 安全建議

- 僅在授權環境啟用。
- 不在公網暴露管理 Web。
- Listener 暴露埠與 Web 管理埠分離。
- 定期清理會話、任務、payload 和事件。
- 演練結束後關閉監聽器並刪除無用 payload。
- 保留必要審計證據，但不要長期儲存敏感輸出。

## 排錯

監聽器無法啟動：

- 埠被佔用。
- 許可權不足，低埠需要額外許可權。
- 防火牆或安全組未放行。

會話不上線：

- payload 回連地址錯誤。
- 目標無法訪問監聽器。
- TLS/Profile 不匹配。
- 被安全產品阻斷。

任務無結果：

- 會話 sleep 較長。
- 會話已離線。
- 命令在目標端卡住。
- 結果過大，需要透過結果檔案下載。

## 生命週期視角

C2 的正確使用不是“建立 listener 然後下命令”，而是一個生命週期：

1. 授權確認：專案、目標、時間視窗、允許動作。
2. Profile 設計：通訊方式、sleep、回連地址、檔案通道。
3. Listener 啟動：確認埠、網路路徑和日誌。
4. Payload 生成：記錄 hash、用途、投遞方式。
5. Session 接入：確認目標身份、許可權和環境。
6. Task 下發：只執行與授權目標一致的任務。
7. 結果歸檔：必要輸出寫入專案事實或報告。
8. 清理：停止 listener、刪除 payload、清理 session/task/event。

跳過前兩步會導致後續每個操作都不可審計。

## 任務分級

| 等級 | 示例 | 審批建議 |
| --- | --- | --- |
| L1 只讀識別 | `whoami`、主機名、當前目錄 | 可由審計 Agent 放行 |
| L2 環境列舉 | 網路介面、程序、使用者組 | 建議人工或嚴格審計 |
| L3 檔案訪問 | 讀取配置、下載結果檔案 | 人工確認目標和路徑 |
| L4 執行變更 | 上傳檔案、修改 sleep、執行指令碼 | 人工審批 |
| L5 持久化/橫向/破壞 | 自啟、憑證、刪除、加密、擴散 | 預設拒絕，除非授權明確 |

把這個分級寫進 HITL 提示詞，比單純“危險則拒絕”更可操作。

## 事件覆盤

一次 C2 操作覆盤至少回答：

- 哪個 listener 接收了哪個 session？
- payload 是誰生成的，什麼時候生成的？
- session 屬於哪個授權目標？
- 下發了哪些 task？
- task 輸出是否寫入報告或專案事實？
- 是否停止 listener 並清理 payload？

如果這些問題答不上來，說明 C2 過程管理還不夠閉環。
