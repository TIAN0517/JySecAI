- Severity: **high**
- Status: confirmed
- Type: 鉴权配置错误 / Mixed Pattern
- Target: `https://epcr.tpf.gov.tw:4004/ 全部端点（Web + Socket.IO + /captcha）`
- Conversation: `c540ef6b-4c80-4589-8e93-ff57dd1bb32e`

## Description

4004 authServer 鉴权层出现严重的 mixed pattern 不一致：Web 端点（/version, /config, /health, /api/login）均通过 express-jwt 中间件严格鉴权（返回 401 "No authorization token was found"），但 Socket.IO 端点 + /captcha 完全无鉴权。这种不一致使得攻击者可绕过 HTTP 鉴权层，通过未受保护的入口（Socket.IO + /captcha）进行攻击，是典型的鉴权层配置错误。

## Preconditions

无（无需任何凭证）

## Reproduction

1. curl -k 'https://epcr.tpf.gov.tw:4004/version' → 401
2. curl -k 'https://epcr.tpf.gov.tw:4004/socket.io/?EIO=4&transport=polling' → 200 + SID
3. curl -k 'https://epcr.tpf.gov.tw:4004/captcha' → 200 + GIF
4. 对比三组响应，确认鉴权层 mixed pattern
5. python3 sio_4004_ws.py → WS upgrade 成功 + 业务事件投递 silent timeout

## Impact

1. 鉴权层不一致：Web 严格鉴权 + Socket.IO + /captcha 无鉴权，攻击者可绕过 HTTP 鉴权层
2. 攻击面扩大：Socket.IO 是实时通信入口，绕过鉴权后可建立长连接（DoS）+ 探测业务事件名 + 尝试认证绕过
3. 配置错误暴露：W/"b7-kloRtePNJdI0rdqUwM/x3w" etag 指纹表明是 express-jwt 中间件模板（不是手工编写），说明鉴权层配置疏忽而非有意设计
4. 横向攻击基础：可作为攻击其他微服务（4000/4001/4002/4006）的横向入口

## Recommendation

1. 统一鉴权层：使用 app.use(authMiddleware) 全局应用，或在 Socket.IO 启动时使用 io.use(authMiddleware)
2. 对所有路由（包括 /captcha）启用统一鉴权中间件
3. 鉴权中间件覆盖：HTTP 路由 + Socket.IO 层 + WebSocket 层
4. 添加鉴权层一致性测试（CI/CD 阶段自动检测 mixed pattern）
5. 定期审查路由列表，确保无遗漏
