## Description

The "菩薩護照" (BuddhaPassport) web app at https://ap.tzuchi.net/BuddhaPassport/ ships vconsole@3.2.0 (a mobile web debug console) in production, loaded from cdn.jsdelivr.net/npm/vconsole and instantiated via `new VConsole()`. A debug console should not be present in a production build. It exposes in-browser debug tooling (network, element, storage, system info) to end users and can leak internal logs, API request/response details, and application internals, aiding further attacks on the app.

## Reproduction

1) Open https://ap.tzuchi.net/BuddhaPassport/ in a browser.
2) Locate the VConsole floating button (bottom-right) or evaluate `new VConsole()` is present.
3) Confirm the debug console panel opens, exposing Network/Storage/Element/Log tabs of the production app.
4) Confirm the source HTML references vconsole@3.2.0 from CDN and instantiates VConsole.

## Evidence

From https://ap.tzuchi.net/BuddhaPassport/ (67,583B HTML), the following are present in production:
  <script src="https://cdn.jsdelivr.net/npm/vconsole@3.2.0/dist/vconsole.min.js">
  new VConsole()   (instantiated)
  new VConsole()   (second instantiation)
vconsole occurrences in the served page: 5.

## Impact

An attacker interacting with the app can open the VConsole UI (typically a floating button) to inspect network traffic, storage, DOM, and system information of the production app. This lowers the barrier to mapping the app's API and internal state, and may expose debug logs or tokens, widening the attack surface.

## Recommendation

Remove vconsole from production builds (gate it behind a dev-only flag or build-time environment check). Audit for other debug tooling (Angular devtools, React DevTools, webpack HMR) in production bundles.
