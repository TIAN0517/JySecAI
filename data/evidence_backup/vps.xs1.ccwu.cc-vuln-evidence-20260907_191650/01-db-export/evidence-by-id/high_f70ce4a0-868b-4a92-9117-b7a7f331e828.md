# 4004 POST /ssoLogin 端點暴露單點登錄認證邏輯（無需認證）

- ID: `f70ce4a0-868b-4a92-9117-b7a7f331e828`
- Severity: **high**
- Status: open
- Type: 認證系統信息洩露
- Target: `https://epcr.tpf.gov.tw:4004/ssoLogin`
- Conversation: `d616190f-0d59-4d31-882b-33ba2ea72121`
- Created: 2026-08-29 19:00:15.362421302+08:00

## Description

4004 認證系統的 POST /ssoLogin 端點接受任意 sessionId 輸入並響應，明確區分「無效格式」(400) 與「無效用戶」(403)。雖然 JWT 認證攻擊失敗，但這個端點暴露了單點登錄的邏輯入口，且接受 NoSQL 操作符和 JWT 格式字符串，可能被用於認證旁路或會話固定攻擊。

## Preconditions

無需認證。直接訪問 https://epcr.tpf.gov.tw:4004/ssoLogin 即可。

## Reproduction

1. 從任意客戶端發送 POST 請求到 https://epcr.tpf.gov.tw:4004/ssoLogin
2. Content-Type: application/json
3. Body 為 JSON：`{"sessionId":"任意字符串"}`（可為空、JWT-like、NoSQL 對象、數組等）
4. 觀察：
   - 空字符串/null/缺 key → 400 "invalid sessionId"
   - 任何其他值 → 403 `{"name":"ErrorWithStatusCode","message":"無法辨識使用者","code":403}`
5. 對比：/login 返回 500，/refreshToken 返回 400 "Invalid refresh token"，/Activities/logoutRecord 返回 401
6. /ssoLogin 是唯一返回 403「無法辨識使用者」的端點，表明認證代碼路徑可達

## Evidence

**測試結果**：
- POST /ssoLogin `{"sessionId":""}` → 400 "invalid sessionId"（純文本）
- POST /ssoLogin `{}` → 400 "invalid sessionId"
- POST /ssoLogin `{"sessionId":null}` → 400 "invalid sessionId"
- POST /ssoLogin `{"sessionId":"abc123"}` → 403 `{"name":"ErrorWithStatusCode","message":"無法辨識使用者","code":403}`
- POST /ssoLogin `{"sessionId":"eyJ.eyJ.sig"}` → 403 同上（JWT-like）
- POST /ssoLogin `{"sessionId":{"$ne":1}}` → 403 同上（NoSQL 嵌套）
- POST /ssoLogin `{"sessionId":["a","b"]}` → 403 同上（數組）

**其他端點對照**：
- POST /login → 500 "TypeError"
- POST /refreshToken → 400 "Invalid refresh token"
- POST /Activities/logoutRecord → 401 "No authorization token was found"

**源碼確認**：AuthService.js 第 73-83 行明確包含 ssoLogin(sessionId) 函數。

**重要**：這是除 /login 外**唯一**接受任意輸入並返回業務邏輯錯誤的端點，暴露了認證系統的內部結構。

## Impact

**嚴重程度高**：
1. **認證系統內部結構暴露** - 攻擊者可確認單點登錄功能存在並理解錯誤邏輯
2. **會話固定攻擊目標** - 如果未來發現任何可預測的 sessionId 格式，可直接利用此端點
3. **錯誤信息洩露** - 中文錯誤響應透露認證系統的中文化業務邏輯
4. **認證旁路潛力** - 若未來發現 captive sessionId（如 SSO 重定向洩露的 token）可直接調用
5. **業務邏輯枚舉** - 通過 sessionId 類型變體可探測後端代碼路徑

## Recommendation

1. **限制 /ssoLogin 端點信息洩露**：對於無效 sessionId 統一返回 401 而非 400/403 區分
2. **添加 IP 白名單**：ssoLogin 應僅從可信 SSO 服務器 IP 調用
3. **加強 sessionId 校驗**：對 sessionId 進行強類型檢查（必須為 32+ 字符的隨機字符串）
4. **記錄失敗嘗試**：增強對 ssoLogin 失敗的日誌記錄，檢測暴力枚舉
5. **撤銷/重置 session**：發現失敗 ssoLogin 時應立即撤銷相關 SSO session
