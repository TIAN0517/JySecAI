## Description

4006 MerBridge 所有路径和 HTTP 方法均返回 403 "Access denined"（注意 typo "denined" 而非 "denied"），表明使用 Express 中间件进行访问控制但存在拼写错误。x-powered-by=Express 公开暴露 Express 框架指纹。OPTIONS /events 返回 204 暴露 GET, HEAD, PUT, PATCH, POST, DELETE 完整方法 + vary: Origin + access-control-allow-origin 反射任意 Origin，表明 CORS 已配置但路由层 403 锁死。攻击者可通过 x-powered-by 指纹识别框架，通过 CORS 反射测试 CSRF 攻击面。

## Preconditions

无（无需任何凭证）

## Reproduction

1. curl -k 'https://epcr.tpf.gov.tw:4006/' → 403 + "Access denined"
2. curl -k -X OPTIONS 'https://epcr.tpf.gov.tw:4006/events' → 204 + allow + ACAO
3. curl -k -X POST 'https://epcr.tpf.gov.tw:4006/events' -H 'Origin: https://evil.com' → 403 + "Access denined"
4. 检查响应头：x-powered-by=Express + access-control-allow-origin: https://evil.com（反射）
5. 尝试所有 Host/X-Forwarded-For/Referer/Cookie/Authorization 绕过均失败

## Evidence

步骤 1：根路径测试
GET / → 403 Forbidden + "Access denined"（typo）
GET /socket.io/ → 403 Forbidden + "Access denined"（typo）
x-powered-by: Express

OPTIONS /events → 204 No Content

DELETE /events → 403 "Access denined"

步骤 4：绕过测试

结论：所有绕过尝试均失败，403 锁死基于 token/session 或 IP 白名单（非简单 Host 绕过）

## Impact

1. 框架指纹暴露：x-powered-by=Express + typo "denined" 暴露 Express 中间件模板 + 配置错误
2. CORS 反射风险：access-control-allow-origin 反射任意 Origin，可能被用于 CSRF 攻击（需结合具体路由测试）
3. 方法暴露：OPTIONS 暴露完整 HTTP 方法（GET/HEAD/PUT/PATCH/POST/DELETE），攻击者知道可用的攻击面
4. 配置错误：typo "denined" 表明中间件代码未经过 code review，可推测其他配置错误

当前 403 锁死状态下无直接利用价值，但提供了大量侦察信息用于后续针对性攻击。

## Recommendation

1. 修正 typo："Access denined" → "Access denied"
2. 移除 x-powered-by 头：app.disable('x-powered-by')
3. 限制 CORS：不要反射任意 Origin，仅允许白名单 Origin
4. 限制 OPTIONS 暴露：仅暴露必要的 HTTP 方法
5. 对 403 错误使用统一错误页，避免暴露中间件信息
6. 实施 IP 白名单 + Token 校验 + Rate Limiting 三层防御
