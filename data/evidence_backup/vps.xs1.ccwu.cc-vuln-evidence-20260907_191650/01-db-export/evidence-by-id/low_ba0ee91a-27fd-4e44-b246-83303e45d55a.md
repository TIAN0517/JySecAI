## Description

tool.tzuchi-org.tw hosts a "tracking" service that exposes an MCP (Model Context Protocol) endpoint at /tracking/mcp (returns 401 without auth) plus an unauthenticated health check at /tracking/health (200 "ok"). The presence of an MCP server endpoint in production, alongside the drust multi-tenant BaaS SPA (/drust/login, 105KB) and a Google OAuth integration, indicates a modern AI/tooling stack deployed on the platform. The MCP endpoint is auth-gated (401), so no direct data exfiltration was achieved, but the exposed service surface (tracking + MCP + BaaS) widens the attack area and warrants review of its authorization, the auth mechanism protecting it, and whether the auth token is brute-forceable or predictable.

## Reproduction

1) curl https://tool.tzuchi-org.tw/tracking/health -> 200 "ok".
2) curl -X POST https://tool.tzuchi-org.tw/tracking/mcp -H 'Content-Type: application/json' -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}' -> 401.
3) Enumerate other /tracking/* paths to map the service surface.
4) Attempt to discover the auth scheme (token header) and test for brute-force / predictable tokens.

## Evidence

GET https://tool.tzuchi-org.tw/tracking/health -> HTTP 200, body "ok" (2 bytes), content-type text/plain (unauthenticated).
POST https://tool.tzuchi-org.tw/tracking/mcp with JSON-RPC initialize -> HTTP 401 (0 bytes), content-type text/plain.
GET https://tool.tzuchi-org.tw/tracking/ -> HTTP 401.
Also observed: /drust/login 200 (105KB drust SPA), /drust/admin/oauth/google/start 302 (Google PKCE S256), login brute-force rate-limited to 429 after ~12 attempts.

## Impact

The exposed tracking/MCP service is an additional internet-facing attack surface. If the MCP endpoint's authorization is weak (static/predictable token, missing rate limiting, or a broken auth flow), an attacker could invoke server tools or read/write tracked data. Even as auth-gated, the health endpoint and service discovery reduce the cost of targeted attacks on the BaaS and MCP components.

## Recommendation

Confirm the MCP endpoint enforces strong, per-user authentication (not a shared static token) and rate limiting; hide or disable the /health and /tracking endpoints from unauthenticated enumeration if not required; audit the drust BaaS tenant isolation and the Google OAuth callback for open-redirect / token-exchange issues; restrict /tracking to a VPN or auth-gate the whole path.
