# 4004 AuthServer /login 端点对所有输入返回 500 TypeError（登录不可用）

- ID: `5a8242b3-59b2-494e-8bc0-99035392d5f4`
- Severity: **high**
- Status: open
- Type: 可用性/服务端错误
- Target: `https://epcr.tpf.gov.tw:4004/login`
- Conversation: `0e6944a5-643d-4cd9-9a2a-7b1676a25139`
- Created: 2026-09-06 14:38:03.186779595+08:00

## Description

4004 AuthServer 的 /login 端点对所有 POST 输入（含有效 captcha 会话 connect.sid cookie）均返回 HTTP 500，响应体为 "TypeError"（11B）。这表明登录流程在服务端存在未捕获的 TypeError（可能因用户查询、密码比对或 token 生成环节引用了 undefined），导致认证功能对所有用户不可用（可用性缺陷）。同时 /refreshToken、/ssoLogin 等认证相关端点未鉴权即可探测，泄露服务端错误信息。

## Reproduction

1. curl -sS -k -c /tmp/cj.txt "https://epcr.tpf.gov.tw:4004/captcha"（获取 connect.sid）
2. curl -sS -k -b /tmp/cj.txt -X POST "https://epcr.tpf.gov.tw:4004/login" -H "Content-Type: application/json" -d '{"username":"admin","password":"admin123","captcha":"1234"}'
3. 观察：HTTP 500，响应体 "TypeError"（11B）。更换任意 username/password/captcha 结果不变。

## Evidence

# 1. 取得有效 captcha 会话
curl -sS -k -c /tmp/cj.txt "https://epcr.tpf.gov.tw:4004/captcha"  # 17646B GIF, 设置 connect.sid
# 2. 带有效会话 POST /login
curl -sS -k -b /tmp/cj.txt -X POST "https://epcr.tpf.gov.tw:4004/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123","captcha":"1234"}'
# 输出: HTTP 500, body = "TypeError" (11B)
# 无会话时同样 500 "TypeError"。所有 username/password/captcha 组合均 500。
# 对照: /ssoLogin 返回 403 "無法辨識使用者"，/refreshToken 返回 400 "Invalid refresh token"，均正常处理。

## Impact

主认证入口 /login 对所有用户返回 500，用户无法通过表单登录获取 JWT token。若 2FA/SSO/refreshToken 路径也依赖同一后端逻辑，则可能整体认证不可用（DoS）。同时泄露 "TypeError" 服务端异常，辅助攻击者定位后端框架/逻辑。

## Recommendation

1) 服务端捕获并记录 /login 的 TypeError 根因（检查 user lookup / bcrypt compare / jwt.sign 各环节的空值引用）；2) 统一错误处理，避免直接回传 "TypeError"，改为通用错误信息；3) 修复后回归测试登录、2FA、SSO、refreshToken 全链路。
