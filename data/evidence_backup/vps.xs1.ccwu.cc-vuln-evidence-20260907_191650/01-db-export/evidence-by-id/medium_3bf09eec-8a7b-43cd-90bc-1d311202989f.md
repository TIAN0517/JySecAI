## Description

GET https://epcr.tpf.gov.tw:4000/version 无需任何身份验证返回 200 OK，body 为内部构建版本号 "1.6.26080"。同时响应头 Content-Security-Policy 完整列出内网所有微服务端口与外部 GCP IP：CSP 中 default-src/img-src/connect-src 包含 epcr.tpf.gov.tw:4000-4007、:9000、GCP 35.234.50.28、localhost:8100/18081。该端点同时暴露 Express etag 指纹 W/"9-V+hlewerXAh6kU5WK7E4fRnnycU"，用于识别 Express 框架。攻击者无需凭证即可：1) 指纹识别 Express + 内部构建号（用于版本关联漏洞/CVE 匹配）；2) 拿到完整内网微服务拓扑（GCP、内网端口、本地回环端口）；3) 验证目标存活与版本漂移（被动监控变更）。

## Preconditions

无需任何身份验证、Token、Cookie；任何能访问 https://epcr.tpf.gov.tw:4000 的客户端均可触发。

## Reproduction

1. 打开任意 HTTP 客户端（curl / 浏览器）
2. 执行 GET https://epcr.tpf.gov.tw:4000/version
3. 观察 302 → /version/ → 200 OK
4. 响应体 = "1.6.26080"
5. 查看响应头 Content-Security-Policy，可见 epcr.tpf.gov.tw:4000-4007、:9000、35.234.50.28、localhost:8100/18081 完整内网拓扑

## Impact

1) 完全未授权暴露内部构建版本号，可关联该版本已知漏洞或内部版本漂移；
2) CSP 头完整泄露内网微服务拓扑（含 GCP 35.234.50.28、localhost:8100/18081），等同于内网地图公开；
3) Express etag 指纹泄漏技术栈；
4) 持续存活表明该端点长期处于未受保护状态，可作为攻击者侦察的零门槛入口。

## Recommendation

1) 在 /version 前添加授权中间件或至少限制为内部 IP 段访问；
2) CSP 头移除内部 IP 与端口（使用 'self' + 显式公网域名），避免在客户端响应中暴露内网拓扑；
3) 关闭 etag 或改为不含 inode 的弱 etag，避免技术栈指纹；
4) 考虑禁用 x-xss-protection: 0 的同时启用 CSP frame-ancestors（已做）。
