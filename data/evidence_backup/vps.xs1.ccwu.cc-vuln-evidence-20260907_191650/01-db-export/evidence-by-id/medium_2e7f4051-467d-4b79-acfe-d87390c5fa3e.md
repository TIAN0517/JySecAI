# ltc.tzuchi.org.tw hardcoded LINE OAuth client_secret in client-side JavaScript

- ID: `2e7f4051-467d-4b79-acfe-d87390c5fa3e`
- Severity: **medium**
- Status: open
- Type: Sensitive Information Exposure (Hardcoded OAuth Credentials)
- Target: `https://ltc.tzuchi.org.tw/LongtermCareService/ (loginController.js, LINE OAuth)`
- Conversation: `3b694297-0b84-41bc-a589-66652e232956`
- Created: 2026-09-03 05:25:20.012842432+08:00

## Description

The LongtermCareService login frontend JavaScript (loginController.js) on ltc.tzuchi.org.tw hardcodes LINE OAuth credentials in client-side code: client_id=1654066811 and client_secret=4fc7fef6843467861df653aed7327503. Client secrets must never be shipped to the browser. Combined with the exposed Firebase Realtime Database (RTDB) referenced by the app, this exposes third-party authentication integration secrets to any visitor. An attacker with the LINE client_secret can impersonate the app to the LINE OAuth provider (code/token exchange on the redirect URI), potentially obtaining LINE user access tokens for the app's scope, and can pivot to the Firebase RTDB if its rules are permissive.

## Reproduction

1) Download the LongtermCareService app JS: fetch https://ltc.tzuchi.org.tw/LongtermCareService/ and locate loginController.js.
2) Grep for client_id / client_secret.
3) Observe client_id=1654066811 and client_secret=4fc7fef6843467861df653aed7327503 hardcoded.
4) Using these creds, request a LINE OAuth token to confirm the secret is live.

## Evidence

From the loginController.js served by https://ltc.tzuchi.org.tw/LongtermCareService/ (Angular app), the LINE OAuth init contains:
  client_id: "1654066811"
  client_secret: "4fc7fef6843467861df653aed7327503"
(verified present in the previously fetched loginController.js; the same app also references a Firebase Realtime Database config for real-time messaging.)

## Impact

Exposure of an OAuth client_secret in public JS breaks the confidentiality assumption of the OAuth flow. An attacker can use the client_id+client_secret to request LINE tokens (if the redirect URI is predictable / open) or abuse the app's LINE scope. The co-located Firebase RTDB config widens the data-exposure surface (consistent with the unauthenticated data reads seen elsewhere on the platform). This is a sensitive-configuration/info-disclosure weakness.

## Recommendation

Remove the client_secret from client-side code; perform the OAuth token exchange on the backend using the secret via a server-to-server call. If LINE supports it, use a PKCE flow that does not require a public client secret. Rotate the exposed client_secret. Audit the Firebase RTDB security rules to deny unauthenticated reads.
