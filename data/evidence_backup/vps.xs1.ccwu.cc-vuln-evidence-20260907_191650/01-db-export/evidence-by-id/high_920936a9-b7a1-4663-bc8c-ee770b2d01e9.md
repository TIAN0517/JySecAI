## Description

【重复开单，canonical=182df1e4-ab82-4705-b61c-1b8546886516。战情挂在 finding/4004-mixed-pattern-auth-inconsistency + finding/4004-socketio-auth-bypass-confirmed，不另开条。】

4004 authServer Socket.IO 层完全无鉴权，与 Web 层 express-jwt 严格鉴权形成鲜明对比。Socket.IO 端点接受匿名连接并返回 SID，业务事件投递静默丢弃或主动断连。Web 端点 (/version, /config, /health, /api/login) 均 401 "No authorization token was found"，但 Socket.IO 根 NS + 9 个 NS 变体 + /captcha 均无鉴权。表明 express-jwt 中间件仅覆盖了 HTTP 路由层，未继承到 Socket.IO 层 + 未覆盖 /captcha。攻击者可绕过 HTTP 鉴权通过 Socket.IO 进行认证相关攻击。

## Preconditions

无（无需任何凭证/认证）

## Reproduction

1. curl -k 'https://epcr.tpf.gov.tw:4004/socket.io/?EIO=4&transport=polling' → 200 OK + SID
2. curl -k 'https://epcr.tpf.gov.tw:4004/version' → 401 "No authorization token was found"
3. curl -k 'https://epcr.tpf.gov.tw:4004/captcha' -o /tmp/captcha.gif → 200 OK + GIF89a + connect.sid
4. python3 sio_4004_ws.py → WS upgrade 成功 + SID + 业务事件投递 silent timeout / SSL EOF
5. python3 sio_4004_ws_events.py → 32 种事件名变体测试，确认 client.* 触发 SSL EOF，其他 silent timeout

## Impact

1. 认证逻辑绕过：HTTP 层鉴权无法保护 Socket.IO 层，攻击者可绕过 JWT 校验建立实时连接
2. 拒绝服务：长轮询挂起（25s pingInterval）可被用于 DoS 攻击，消耗 Socket.IO 服务资源
3. 信息泄露：可通过 Socket.IO 探测业务事件名识别、订阅模型（roomName）、事件路由策略（client.* 主动断连）
4. 横向攻击：AuthServer 是整个 EPCR 系统的认证中心，绕过鉴权后可作为攻击其他微服务（4000/4001/4002/4006）的横向入口

## Recommendation

1. 在 Socket.IO server 启动时使用 io.use((socket, next) => { /* JWT 校验 */ }) 中间件，对所有 Socket.IO 连接进行 JWT 校验
2. 对所有 HTTP 路由（包括 /captcha）启用统一鉴权中间件，避免 mixed pattern
3. 业务事件名加入权限位校验，区分通用事件与敏感事件（client.* 前缀触发主动断连是临时缓解措施，应在中间件层统一处理）
4. 实施 IP 风控 + 速率限制，避免单 IP 大量探测消耗资源
