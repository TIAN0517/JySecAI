- Severity: **medium**

- Type: Information Disclosure / 信息泄露

## Description

EPCR 医疗系统的 /config 端点在 4000、4002、4003 三个端口上均无需认证即可访问，返回完整的 JSON 配置信息，泄露内部微服务拓扑、外部域名、RTMP 流媒体地址、版本号和会话配置等敏感信息。

## Reproduction

1. 打开终端
2. 执行命令: `curl -sk "https://epcr.tpf.gov.tw:4000/config"`
3. 观察响应状态码: 200 OK
4. 解析 JSON 响应，查看配置信息
5. 验证包含 EPCRServer、vitalSignVideoServer、MerServer 等字段
6. (可选) 测试 4002 和 4003: 
   - `curl -sk "https://epcr.tpf.gov.tw:4002/config"`
   - `curl -sk "https://epcr.tpf.gov.tw:4003/config"`

## Impact

1. **内部架构泄露**: 暴露 9 个内部微服务端口 (4000-4008, 9000) 和 2 个外部服务 (mer2.tpf.gov.tw:7000, mer2voip.tpf.gov.tw:30080)
2. **RTMP 流媒体地址**: rtmp://mer2voip.tpf.gov.tw/rtmp/live 暴露内部流媒体服务器
3. **实时视频 URL 模式**: 攻击者可能通过枚举 dispatchRecordUuid 和 recordUuid 访问实时视频流
4. **版本信息**: 1.6.26080 可帮助攻击者查找已知漏洞
5. **会话配置**: MAX_IDLE_DURATION=900000ms (15分钟) 和 NO_IDLE_DETECTION_STATES 暴露会话管理逻辑
6. **云门户**: cloud2.ntpc.gov.tw 暴露云基础设施
7. **攻击面扩大**: 攻击者可基于这些信息对其他服务进行针对性攻击

## Recommendation

1. **移除 /config 端点**: 如果仅用于开发/调试，应在生产环境移除
2. **添加认证**: 如果必须保留，添加 JWT 认证中间件
3. **最小化信息**: 仅返回前端必需的配置，隐藏内部服务 URL
4. **使用环境变量**: 将敏感配置存储在环境变量中，而非硬编码在 API 响应中
5. **配置管理**: 使用配置管理工具 (如 Vault) 管理敏感配置
6. **API 文档**: 在 API 文档中明确标注 /config 为内部端点，不应公开访问

**验证方法:**
修复后，无 Token 访问应返回 401 或 404:
```bash
curl -sk "https://epcr.tpf.gov.tw:4000/config"
# 期望: 401 Unauthorized 或 404 Not Found
```
