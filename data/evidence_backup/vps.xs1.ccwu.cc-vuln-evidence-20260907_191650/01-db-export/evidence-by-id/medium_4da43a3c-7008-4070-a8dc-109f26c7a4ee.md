## Description

【重复开单，canonical=6f0c0d50-181e-4ae5-949d-0f8e94f00dca。战情已钉 finding/4004-login-typeerror-retest-20260831 + finding/4004-login-route-crash-all-payloads-500-typeerror，不另开条。connect.sid 见 finding/4004-connect-sid-cookie；ssoLogin/refreshToken 已有独立 fact。注意：GET /captcha 是 200 不是 404。】

4004 auth 服务 POST /login 在缺少必填字段（username/password/captcha）时未做输入校验，触发未捕获的 TypeError 返回 HTTP 500 + 响应体 "TypeError"。

证据：
POST /login {"username":"","password":""} → HTTP 500, body "TypeError"
POST /login {"username":"admin","password":"admin"} → HTTP 500, body "TypeError"

所有 4004 响应（甚至 4xx）都 Set-Cookie: connect.sid=s:<base64 sig> — 即使失败的认证请求也会建立 express-session，可被攻击者收集用于会话固定/会话持久性。

同时 GET /login /ssoLogin /refreshToken /captcha 返回 404（路由仅响应 POST），暴露服务端存在这些端点。

## Preconditions

无需前置条件 - 完全无认证即可触发

## Reproduction

1. curl -k -X POST 'https://epcr.tpf.gov.tw:4004/login' -H 'Content-Type: application/json' -d '{"username":"","password":""}'
2. 观察 500 + body "TypeError" + Set-Cookie connect.sid
3. curl -k -X POST 'https://epcr.tpf.gov.tw:4004/ssoLogin' -H 'Content-Type: application/json' -d '{"sessionId":"00000000-0000-0000-0000-000000000000"}'
4. 观察 403 + "無法辨識使用者" + Set-Cookie connect.sid

## Evidence

POST /login {"username":"","password":""} → HTTP 500 + body: "TypeError" + Set-Cookie: connect.sid=s%3AsTkaBAHRoIotAFDDCjhjN3GlEeSR5_QT.w00qbi5VCzzXd3GfW8va4se6hrvn4YQii7MuqbUtum0; Path=/; HttpOnly

POST /login {"username":"admin","password":"admin","captcha":""} → HTTP 500 + "TypeError"

POST /ssoLogin {"sessionId":""} → 400 "invalid sessionId"
POST /ssoLogin {"sessionId":"00000000-0000-0000-0000-000000000000"} → 403 {"name":"ErrorWithStatusCode","message":"無法辨識使用者","code":403}
POST /refreshToken {"refreshToken":""} → 400 {"name":"ErrorWithStatusCode","message":"Invalid refresh token","code":400}
POST /refreshToken {"refreshToken":"<任意 JWT>"} → 400 Invalid refresh token

OPTIONS 全部 204，CORS 全开。
所有 4004 响应含 CSP、X-XSS-Protection: 0、x-content-type-options: nosniff 等安全头，但 x-xss-protection 关闭浏览器过滤。

## Impact

high - 1) 错误处理不当可被指纹识别后端为 Node.js/Express；2) connect.sid 即使 4xx 也下发，攻击者可收集无意义 session 用于钓鱼或填充；3) 端点枚举（login/ssoLogin/refreshToken/captcha）确认后端模块结构，便于后续凭据喷洒/会话固定攻击；4) 与 ssoLogin 端点结合：若攻击者能窃取任一合法用户 sessionId 可无密码获取 JWT。

## Recommendation

1) login/ssoLogin/refreshToken 路由增加 try/catch 错误处理中间件；2) 错误响应统一为 {"error":"invalid request"} 不暴露 TypeError；3) 失败的认证请求不 Set-Cookie connect.sid；4) 启用 rate limit 防爆破；5) ssoLogin 验证来源 IP / SSO 签名而非裸 sessionId；6) JWT 签名启用 RS256 + 强密钥。
