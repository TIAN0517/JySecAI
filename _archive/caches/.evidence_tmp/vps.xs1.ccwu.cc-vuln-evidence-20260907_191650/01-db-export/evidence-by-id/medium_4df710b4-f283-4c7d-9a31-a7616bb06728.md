# 4002 /config 端点泄露完整微服务拓扑与 captcha 配置（无需认证）

- ID: `4df710b4-f283-4c7d-9a31-a7616bb06728`
- Severity: **medium**
- Status: open
- Type: 信息泄露 / 配置错误
- Target: `https://epcr.tpf.gov.tw:4002/config`
- Conversation: `c540ef6b-4c80-4589-8e93-ff57dd1bb32e`
- Created: 2026-08-29 20:26:17.485352749+08:00

## Description

GET https://epcr.tpf.gov.tw:4002/config 无需任何认证返回 200 OK + 完整微服务拓扑 JSON。泄露内容包含：SELF_URL/EPCRServer/authServer/vitalSignVideoServer/MerBridge/Redir/MerServer/captcha 配置。这与 /js/publicConfig.js 客户端常量完全一致，说明服务端 /config 端点未做任何访问控制且无认证要求。攻击者可利用此信息进行针对性横向渗透（如已知 authServer 是 JWT 颁发服务，可针对 /login 端点爆破；已知 MerBridge 端口可针对性探测；已知 Redir URL 可构造 OAuth/SSO 钓鱼链）。

## Reproduction

1. 任意机器运行 curl -sk https://epcr.tpf.gov.tw:4002/config
2. 观察响应：HTTP 200 + 完整 JSON 微服务拓扑
3. 无需任何 Authorization/cookie/query 参数
4. 浏览器直接访问 https://epcr.tpf.gov.tw:4002/config 也可直接查看

## Evidence

curl -sk https://epcr.tpf.gov.tw:4002/config
响应：
HTTP/1.1 200 OK
Access-Control-Allow-Origin: *
Content-Type: application/json; charset=utf-8
Content-Length: 271
{"SELF_URL":"https://epcr.tpf.gov.tw:4002","EPCRServer":"https://epcr.tpf.gov.tw:4000","authServer":"https://epcr.tpf.gov.tw:4004","vitalSignVideoServer":"https://epcr.tpf.gov.tw:4001","MerBridge":"https://epcr.tpf.gov.tw:4006","Redir":"https://mer2.tpf.gov.tw/Views/CreateSession.aspx","MerServer":"https://mer2.tpf.gov.tw","captcha":{"enable":true,"captchaImg":"/captcha"}}

公开 JS bundle 中 /js/publicConfig.js 内容与 /config 完全相同（gzip 405B），证明服务端该 JSON 与前端常量同源。

注意：4002 根 NS 已有漏洞 G（鉴权层完全失效），意味着该 /config 端点同样可绕过鉴权访问（同一 host:port 同一服务器进程）。

## Impact

1. 完整内部微服务架构披露，攻击者无需再做端口/服务发现
2. 横向利用线索明确：authServer:4004（认证服务）→ 优先爆破 /login 端点（已知 body 格式 {username, password, captcha}）；vitalSignVideoServer:4001（视频服务）→ 可能存储医疗视频；MerBridge:4006（医疗信息桥接）→ 高敏感度
3. captcha.enable=true 但 captchaImg 相对路径暴露 → captcha 端点可绕过
4. 与漏洞 G 形成完整攻击前置：漏洞 G 绕过鉴权 + 本漏洞暴露拓扑 → 横向利用更精准

## Recommendation

1. 对 /config 端点增加与根 NS 一致的 express-jwt 鉴权中间件（或要求 service-to-service token）
2. 将敏感 URL（authServer/MerBridge/vitalSignVideoServer 等）改为内部 DNS 主机名而非公网域名/IP
3. 对 captcha 端点单独加强防护（如限速、IP 白名单）
4. 在 WAF/反代层对包含"Server"、"Auth"、"Internal"等关键词的端点进行访问控制
