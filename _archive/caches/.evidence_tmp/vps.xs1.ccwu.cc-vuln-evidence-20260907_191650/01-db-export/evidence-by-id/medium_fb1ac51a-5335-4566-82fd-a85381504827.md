## Description

The EPCRServer config endpoint https://epcr.tpf.gov.tw:4000/config is publicly accessible without any authentication and returns a full JSON blob describing the entire application's internal service topology. The response contains every internal service URL and endpoint: epcrServer, vitalSignVideoServer (4001), HospitalServer (4002), doctorServer (4003), authServer (4004), monitorServer (4005), merBridge (4006), merServer (mer2.tpf.gov.tw:7000), statUrl (4007), mciServer (4008), printServer (9000), ntpcCloud (cloud2.ntpc.gov.tw), the RTMP video streaming host (rtmp://mer2voip.tpf.gov.tw/rtmp/live), real-time MSE video path (mer2voip.tpf.gov.tw:30080/live), plus video/voice/image data file endpoints and captcha config. This gives an unauthenticated attacker a complete internal architecture map including internal subdomains, ports, and media-streaming hosts that can be used as high-value targets for follow-on attacks.

## Reproduction

1. Without logging in, open GET https://epcr.tpf.gov.tw:4000/config in a browser or: curl -sk "https://epcr.tpf.gov.tw:4000/config"
2. Observe HTTP 200 and a JSON object enumerating all internal services (ports 4001-4008, 9000, mer2.tpf.gov.tw:7000, cloud2.ntpc.gov.tw, mer2voip.tpf.gov.tw RTMP/MSE, data-file paths).
3. Cross-reference these hosts against the running attack surface.

## Impact

Unauthenticated disclosure of the full internal service topology, including non-obvious internal hosts (mer2.tpf.gov.tw:7000, cloud2.ntpc.gov.tw, mer2voip.tpf.gov.tw:30080 RTMP/MSE video streaming) and data-file retrieval paths (/videoData/getFile/, /imageData/getFile/, /voiceData/getFile/). This dramatically reduces reconnaissance effort for an attacker and directly enables targeting of lower-profile internal services and media/data endpoints (including potential IDOR on the getFile paths) that would otherwise require broad discovery. It is a textbook sensitive-information-disclosure / insecure-configuration finding.

## Recommendation

Remove or protect the /config endpoint: serve only the minimal client-required subset behind authentication, or split it into a public safe-config and a server-side-only config. Remove internal service URLs, RTMP hosts, and internal data-file paths from the public payload. Re-test that unauthenticated GET /config no longer reveals internal topology.
