## Description

4001 vitalSignVideoServer Express+Sequelize 应用 POST /trendings 端点无需任何认证，可直接写入 /trendings 业务时序数据。POST body 在 recordUuid/CaseID 字段级有 Sequelize string violation 拦截（不允许对象/数组），但以下三处 validation 缺失导致严重攻击面：

1. **顶层 $or / 数组 body 无校验**：直接 POST `{"$or":[{"recordUuid":"X1"},{"recordUuid":"X2"}]}` 或 `[{...},{...}]` 都返回 201 成功，但 recordUuid 被强制设为 null，产生大量 recordUuid=null 的脏数据。
2. **fileId 字段无类型校验**：fileId 接受 `{"$gt":0}` / `{"x":1}` / `"abc"` 字符串 / `{"$ne":-1}` 等任意值，全部 201 成功。
3. **真实病患 recordUuid 可被任意覆盖**：实测用 `recordUuid=3a5ba9bc-ca70-44dd-9d59-88742b6a2bc4`（来自真实病患 /imageData id=1011277）+ `hr=999`+`spo2=999` POST 直接成功（返回 id=1007546），污染进生产数据库。医生在做诊断时看到该病患生命体征异常会被误导。

端点对应的 /trendings GET 端点同源无鉴权，可被攻击者立即读取所有写入数据做交叉验证。

业务字段 hr/pulseRate/spo2/respRate/temperature/etco2/cpp/nbp/NBPd/NBPs/NBPm/ABP/Ao/ART/PAP/RAP/CVP/LAP/ICP/P1/P2/unspecific 全部接受任意数值/字符串写入，没有任何业务校验。

## Reproduction

1. 无需任何凭据/captcha/JWT,直接访问 POST https://epcr.tpf.gov.tw:4001/trendings
2. Body: {"recordUuid":"任意字符串","fileId":任意整数} -> 201 Created + id 自动分配
3. GET https://epcr.tpf.gov.tw:4001/trendings?recordUuid=<刚写入> -> 200 + 立即可读
4. 真实污染复现: Body: {"recordUuid":"3a5ba9bc-ca70-44dd-9d59-88742b6a2bc4","hr":999} -> 201 + 数据入库
5. 字段注入: Body: {"recordUuid":"X","fileId":{"$gt":0}} -> 201 + fileId 注入
6. 顶层 NoSQL: Body: {"$or":[{"recordUuid":"A"},{"recordUuid":"B"}]} -> 201 + 脏数据 recordUuid=null

## Impact

1. PHI 数据完整性破坏: 真实病患生命体征被任意覆盖,医生诊断被误导,可能造成医疗事故 (vital signs 显示心率 999/SpO2 999 会被解读为危急状态)
2. 数据库污染: 顶层 $or + 数组 body 绕过 validation,可批量写入 recordUuid=null 脏数据,干扰业务统计与机器学习模型训练
3. 字段级 NoSQL 注入面: fileId 字段任意对象/数组注入,潜在 Sequelize ORM 注入扩展点
4. 与 finding/4001-imagedata-noauth-full-disclosure 形成组合攻击: 通过已泄露的真实病患 recordUuid,可进一步污染其 trendings 时序数据
5. 删除操作不可用 (DELETE 404),数据一旦污染只能通过工单清理,影响生产数据治理
6. 攻击门槛极低: 无认证、无 captcha、无 JWT、无 referer 校验,可被自动化脚本批量利用

## Recommendation

1. /trendings 必须加入 express-jwt 中间件,要求有效 JWT 才能 POST 写入 (与 HospitalServer 同源模式)
2. Sequelize model 增加字段级 validate: recordUuid/CaseID 必须是字符串、fileId 必须是整数、hr/spo2/temperature 必须在医学合理范围内 (0-300/0-100/20-45 等)
3. 关闭 Sequelize model 操作符解析,避免 {key: {$gt: x}} 等对象被解析为 Sequelize operator (实际 Sequelize 默认会解析,需在 modelOptions 中显式关闭)
4. 清理已污染数据: DELETE FROM trendings WHERE recordUuid IN ('TestPOC_TRENDING_001','TestNormal_001','TestMin_002','TestMulti_003','TestFileIdGT_001','TestCaseIDNE_001','3a5ba9bc-ca70-44dd-9d59-88742b6a2bc4') OR recordUuid IS NULL AND createdAt > '2026-08-29'
5. 部署 MongoDB-style 注入过滤中间件,识别 body 中含 $ 开头的 key (req.body 解析时过滤)
