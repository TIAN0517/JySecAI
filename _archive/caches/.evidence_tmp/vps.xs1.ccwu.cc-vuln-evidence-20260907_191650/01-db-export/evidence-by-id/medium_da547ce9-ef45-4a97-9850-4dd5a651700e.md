## Description

4001 vitalSignVideoServer Express+Sequelize 应用 PUT /imageData/{id} 端点虽然存在但触发 Sequelize update 流内部错误。无论 body 是什么（包括空 `{}`），都返回 HTTP 500 + `{"message":"internal error","errors":["Invalid parameters."]}`。

这与 /imageData POST 端点完全不同：
- POST /imageData 触发的是 Sequelize model validation 错误（如 `string violation: recordUuid cannot be an array or an object`、`notNull Violation: fileName cannot be null`），返回 HTTP 400
- PUT /imageData/{id} 触发的是 Sequelize update 调用栈的内部错误（"Invalid parameters."），返回 HTTP 500

可能原因：
1. Sequelize update 时缺少必要的 where 条件，导致 Sequelize 安全检查失败
2. Sequelize update 时主键 (id) 与 body 中其他字段冲突
3. 框架中间件层处理 PUT 路由时未正确转发 body 到 Sequelize instance.update()

无论哪种原因，该端点都暴露了：
- 端点存在但不可用 (拒绝服务风险: 端点表面可用但 update 一定失败)
- 错误消息未脱敏 ("Invalid parameters." 直接输出)
- express-jwt 未保护 (无 JWT 即可访问该端点)

实测用 id=1011277（真实病患心电图照片）+ 合法 body `{"recordUuid":"3a5ba9bc-ca70-44dd-9d59-88742b6a2bc4","fileName":"test.jpg","fileId":1}` 和空 body `{}` 都返回相同 500 错误，确认不是用户输入导致的失败，而是 update 流本身的问题。

## Reproduction

1. 无需任何凭据,直接访问 PUT https://epcr.tpf.gov.tw:4001/imageData/1011277
2. Header: Content-Type: application/json, Origin: https://epcr.tpf.gov.tw
3. Body 任意 JSON (测试过 {} 与完整字段): 都不影响响应,始终返回 500 Invalid parameters.
4. 观察响应消息: {"message":"internal error","errors":["Invalid parameters."]}
5. 与 POST /imageData 对比: POST 触发 Sequelize validation 错误 (HTTP 400), PUT 触发 update 内部错误 (HTTP 500)

## Impact

1. 端点表面可用但实际 update 一定失败,构成隐性 DoS (如果业务流依赖该端点)
2. 错误消息泄露 Sequelize 框架实现,辅助攻击者构造更精准的注入 payload
3. PUT 路由未与 POST /imageData 共享 Sequelize validation 层,说明该端点可能已废弃但路由未清理,扩大攻击面
4. express-jwt 未保护 PUT 路由,与 POST 端点鉴权不一致,暴露框架鉴权配置疏忽

## Recommendation

1. /imageData/{id} PUT 必须加入 express-jwt 中间件 (与 POST 端点保持一致)
2. 修复 Sequelize update 流: 检查 Sequelize instance.update({where: {id}}) 调用方式,确保 where 条件正确
3. 全局错误处理中间件对 Sequelize 错误脱敏: 捕获后返回 HTTP 500 + {"message":"internal error"} 而非泄露具体错误消息
4. 清理无用的 PUT/DELETE 路由: 如果不支持 update 操作,应从路由表中删除以减少攻击面
