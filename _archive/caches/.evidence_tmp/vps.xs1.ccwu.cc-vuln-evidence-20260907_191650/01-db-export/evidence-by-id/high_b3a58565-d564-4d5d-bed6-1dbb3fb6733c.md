# 4001 vitalSignVideoServer Socket.IO 完全无鉴权（视频流横向入口）

- Status: open
- Type: 鉴权绕过 / 信息泄露
- Target: `https://epcr.tpf.gov.tw:4001/socket.io/ + Socket.IO 业务事件`

## Description

4001 vitalSignVideoServer Socket.IO 端点完全无鉴权：GET /socket.io/?EIO=4&transport=polling 无 token 直接返回 200 + SID f6LFotyK2pHEydrCABOX + set-cookie io=...; HttpOnly + access-control-allow-origin: *。与 4002 / 4004 同样的漏洞模式（express-jwt 未覆盖 SIO 层）。攻击者可建立匿名 Socket.IO 连接，作为视频流/医疗数据横向入口。vitalSignVideoServer 是处理视频流的关键服务，绕过鉴权可能导致患者视频监控数据泄露。

## Preconditions

无（无需任何凭证）

## Reproduction

1. curl -k 'https://epcr.tpf.gov.tw:4001/' → 200 + Express 默认页
2. curl -k 'https://epcr.tpf.gov.tw:4001/socket.io/?EIO=4&transport=polling' → 200 + SID + set-cookie io=...
3. python3 ws 测试 → WS upgrade 成功 + 业务事件投递 silent timeout / 主动断连
4. 配合 NS 变体测试 + 事件名穷举确认攻击面

## Impact

1. 视频流泄露：vitalSignVideoServer 处理救护车视频流，绕过鉴权可能导致患者隐私数据泄露
2. 实时数据通道：可建立长连接（25s pingInterval）进行实时数据订阅
3. 拒绝服务：长轮询挂起可被用于 DoS 攻击
4. 横向攻击：作为攻击其他微服务（4000/4002/4004/4006）的横向入口

当前仅发现 Socket.IO 鉴权绕过，业务事件路由策略待深入测试（NS + 事件名穷举）。

## Recommendation

1. 在 Socket.IO server 启动时使用 io.use((socket, next) => { /* JWT 校验 */ }) 中间件
2. 对所有 NS 启用统一鉴权（避免与 4002/4004 类似的 mixed pattern）
3. 限制 CORS：access-control-allow-origin 不要设为 *，应使用白名单
4. 实施 IP 风控 + 速率限制
5. 对敏感 NS（如 /admin, /video）启用额外的权限校验
