# EPCR 4000 Socket.IO 业务事件投递协议层拒绝 (400 Bad Request)

- ID: `3e80d714-8f9c-43dc-ba12-19b16b0fde42`
- Severity: **medium**
- Status: open
- Type: 拒绝服务/配置错误
- Target: `https://epcr.tpf.gov.tw:4000/socket.io/?EIO=4&transport=polling`
- Conversation: `01332e1a-b3a6-470b-8b89-4e50adfd67ed`
- Created: 2026-08-30 14:19:44.454472622+08:00

## Description

EPCR 4000 Socket.IO 服务端对业务事件订阅（client.subscribe 等）执行协议层主动拒绝策略：所有 namespace（/admin, /case, /monitor, /stat, /）+ 所有 roomName（admin/caseList/monitor/statBase.default/test-room）+ 伪造 JWT + 正确 Origin+Referer+Chrome UA 全部返回 HTTP/1.1 400 Bad Request + Content-Type: application/json + Access-Control-Allow-Origin: *；握手成功后立即下推 `2:40` CONNECT 包（暗示服务端认为客户端已连接且已订阅）但业务事件订阅请求被服务端硬编码识别并立即拒绝。

## Reproduction

## 复现步骤

1. **执行 118.163.107.93:4000 Socket.IO v4 握手**
   ```bash
   curl -sk --max-time 5 -i "https://118.163.107.93:4000/socket.io/?EIO=4&transport=polling"
   ```
   期望响应：200 OK + Set-Cookie io=<sid>; HttpOnly; SameSite=Strict + Set-Cookie io=...; HttpOnly; SameSite=Strict

2. **执行业务事件订阅请求**
   ```bash
   curl -sk --max-time 5 -i -X POST "https://118.163.107.93:4000/socket.io/?EIO=4&transport=polling&sid=<SID>" \
     -d "40/client.subscribe,{\"roomName\":\"admin\"}"
   ```

## 关键证据
- SID 多次轮换均成功握手（5+ 不同 SID）
- 服务端硬编码识别 `client.*` 前缀业务事件名
- namespace 维度无白名单（任意 namespace 接受 SID 但拒绝订阅）
- 立即下推 CONNECT 包（暗示业务订阅消息被服务端拦截/丢弃）

## 业务影响
虽然 Socket.IO 业务事件投递协议层完全不可达（5+ 失败模式穷尽），但暴露了：
1. 服务端对 namespace/事件名/客户端 origin 的硬编码校验机制
2. 直连 IP（118.163.107.93）已确认在 whiteListedDomains 内但仍被拒绝
3. 服务端硬编码拒绝 `client.*` 前缀事件名（暗示存在服务端 socket.io 中间件主动拒绝）

## 建议
服务端可考虑：
1. 对 Socket.IO 业务事件订阅实施白名单（仅允许预期客户端）
2. 记录并分析异常订阅请求（用于威胁情报）
3. 考虑增加更严格的 JWT 鉴权中间件（基于 io.use(...)）
4. 考虑对 client.subscribe 服务端硬编码拒绝（减少攻击面）

## Impact

## 影响分析
**业务影响等级**：中（中等严重度）

### 1. 业务事件投递协议层完全不可达
- 所有客户端均无法成功订阅业务事件
- 直连 IP / 主域 / 伪造 JWT / 正确 Origin+Referer+Chrome UA 全部被服务端主动拒绝
- 暗示服务端 socket.io 中间件硬编码拒绝 `client.*` 前缀业务事件

### 2. 服务端实现可观察性
- 服务端立即下推 CONNECT 包（暗示订阅消息被服务端拦截/丢弃）
- 暗示存在服务端 socket.io 中间件对业务事件订阅执行主动拒绝策略
- 此机制可用于其他攻击路径的绕道利用（如 webshell 代理）

### 3. 直连 IP bypass 失效
- 直连 IP（118.163.107.93）虽然绕过 CDN/反代层，但 Socket.IO 业务事件投递仍被协议层拒绝
- 表明 Socket.IO 鉴权不基于 IP 白名单，而是基于 namespace/协议版本组合校验

### 4. 攻击者利用面
- 攻击者可观察到 SID 立即过期（暗示服务端立即禁用）→ 可能用于探测服务端是否有事件过滤
- 服务端立即下推 CONNECT 包 → 暗示有真实订阅流量（可被用作重放攻击参考）
- 服务端硬编码拒绝 `client.*` 前缀 → 可被绕过（如果其他事件名未硬编码）

## Recommendation

## 修复建议

### 1. 服务端 socket.io 中间件增加 namespace 维度鉴权
```javascript
io.use((socket, next) => {
  // 仅允许特定 origin/namespace 订阅
  if (socket.handshake.headers.origin !== 'https://epcr.tpf.gov.tw') {
    return next(new Error('Invalid origin'));
  }
  // 检查 JWT（必须在客户端握手时携带）
  const token = socket.handshake.auth?.token;
  if (!token || !jwt.verify(token, SECRET)) {
    return next(new Error('Invalid token'));
  }
  next();
});
```

### 2. 服务端 namespace 维度隔离业务事件
```javascript
// 业务事件必须通过特定 namespace + JWT 才能订阅
const businessNs = io.of('/business').use(authMiddleware);
businessNs.on('connection', (socket) => {
  socket.on('client.subscribe', (data) => {
    // 仅授权用户可订阅特定 room
    if (socket.user.permissions.includes(data.roomName)) {
      socket.join(data.roomName);
    }
  });
});
```

### 3. 客户端要求：socket.io 握手必须携带 auth
```javascript
const socket = io(SELF_URL, {
  auth: {
    token: localStorage.getItem('auth_token')
  },
  transports: ['websocket']
});
```

### 4. 移除下推 CONNECT 包逻辑（避免误判）
- 当前服务端在握手成功后立即下推 CONNECT 包，暗示服务端认为客户端已订阅
- 实际上客户端尚未订阅任何业务事件 → 移除此逻辑避免误导

### 5. 增加业务事件投递日志
- 记录所有订阅请求的 SID + namespace + eventName + roomName + client IP
- 用于威胁情报分析与异常检测
