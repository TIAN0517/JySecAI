# ofa77.shop Laravel APP_DEBUG=true exposes full stack traces and file paths (CWE-209)

- ID: `e6a94ab6-82dd-48cf-8d32-97171278badf`
- Severity: **medium**
- Status: open
- Type: Information Disclosure / Debug Mode
- Target: `https://ofa77.shop/ (all non-existent routes)`
- Conversation: `167240fc-493e-44b3-b0e2-9d5692aa1da1`
- Created: 2026-09-03 17:32:07.511653226+08:00

## Description

The ofa77.shop e-commerce app (Laravel + UnionCMS/Unishop on BaoTa) runs with APP_DEBUG=true. Any request to a non-existent route returns a full Symfony/Laravel exception page (≈55KB) instead of a clean 404. The page renders the complete call stack and dumps the request object via Symfony VarDumper.

## Reproduction

1) GET https://ofa77.shop/<any-nonexistent-path> (e.g. /definitely_not_here_xyz_9931). 2) Observe HTTP 200 with a 54KB page. 3) Search the HTML for "vendor/laravel" and "sf-dump" — the Symfony VarDumper and full Illuminate stack trace with absolute file paths are present.

## Evidence

GET https://ofa77.shop/definitely_not_here_xyz_9931 → HTTP 200, 54617-byte page containing Symfony VarDumper (Sfdump script) + full Illuminate stack trace. Confirmed file paths leaked: /www/wwwroot/ofa77.shop/public/index.php:54, .../vendor/laravel/framework/src/Illuminate/Foundation/Http/Kernel.php:176, .../Routing/Pipeline.php:53, .../Middleware/TransformsRequest.php:31, .../ValidatePostSize.php:27. Full request object (Illuminate\Http\Request #42, 23 occurrences) is dumped with expandable references.

## Impact

Information disclosure: reveals exact web-root path (BaoTa /www/wwwroot/ofa77.shop), framework (Laravel), all loaded PHP file paths and line numbers, and the full HTTP request object (headers/cookies/session) via the VarDumper AJAX endpoint. This aids further exploitation (LFI path targets, framework version pinning, token/cookie inspection) and confirms the app is in an un-hardenized debug state.

## Recommendation

Set APP_DEBUG=false in production .env (and ensure it is not overridden). Ensure the Laravel exception handler returns minimal 404/500 pages for unauthenticated visitors. Re-test: GET a random route should return a clean 404 with no stack trace or file paths.
